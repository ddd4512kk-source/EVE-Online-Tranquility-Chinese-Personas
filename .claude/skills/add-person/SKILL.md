# 添加 / 修订列传

规则全在 `AGENTS.md`（第 2–5 节）。记住一句：**宁收勿漏，有线索就发挥，骨架不能编。**

## 1. 查 ID、查重

先读已有列传、本人素材与共享事件来源，确定此次新增信息；已有 ID／对应关系直接复用。新收录或身份矛盾才运行：

```bash
npm run find -- "<名字或链接>"
```

- 已有列传 → 默认增补；明确要求重写时按其范围重写。动笔前记住现有主线、重要职责和已收红黑料，新增材料不能将它们覆盖。FC、管理等身份不因一桩争议消失。
- 找不到主号 → 用本人小号；帖中署名、截图、同名且军团或时间吻合都算对应依据，记进素材文件。完全对不上才登记 `docs/pending-characters.md`。

## 2. 找料

先复用已有素材与检索记录；只有新线索、相关未查缺口、身份矛盾或明确刷新需要才补查。按 `docs/research-method.md` 选择高回报入口，遵守统一预算与停止规则，普通修订不自动联网。

跨平台认号按 `AGENTS.md` 第 2 节；小号／Monitor 反查按取材手册第六、七节。批量发现人物或回查战役、帖子时改用 `research-community` 管理覆盖，再回本技能写传。

## 3. 撰写

`src/people/<短名>/<短名>.md`（从 `docs/person-template.md` 复制）+ 同目录 `materials-<短名>.md`（来源与检索记录）。

新目录先写有效的同名列传，不先堆只有素材的目录；归档按 `AGENTS.md` 第 6 节总结精炼，多人共用事件只存一份摘要，人物素材写本人增量。

动笔前读 `docs/writing-review.md`，按其中正反例处理来源说法、线索推演与素材缺口。

- `cn_name` 有就填；`aliases` 写外号；`epithet` ≤25 字，多想几版挑最狠的；`tags` 先 `rg "^tags:" src/people/*/*.md` 复用已有；军团标签只用当前收录角色快照里的游戏内 ticker，保留大小写、空格与标点，不能复用中文团名或全名。当前有联盟时必须补齐当前军团 ticker；历史归属不加标签。
- 正文：开篇讲故事 → 红料块 → 黑料块 → `::: 评`。每条料一块。
- 战绩围绕自然人合并叙述，不按主号／小号分段；逐号统计不相加，核对细节留素材。红料保留综合 KB 评价，用人物处境、阵营、舰船与前后经历把已确认战役写成故事，点评穿插其间。素材够就多写，不以逐场参战流水账加末尾一句笑话代替列传。
- 把线索里的利益冲突、人物处境和言行反差展开，主动推测动机、串起前因后果，以“大概”“看样子”领起推测。不满足于原帖摘要加末尾笑话。来源交代一次后继续讲事；核查缺口留素材，细节不明就用概称或来源方估计，不用免责句刹住故事。
- 批量补写先完成少量不同经历的代表人物，自查标题与实际故事、原料保留和人物区别后再扩批；不能用全局替换或同一句笑话解决文风问题。
- 榜单、参战与通用工具分享只作发现入口；仅有泰坦／超旗等战果签名、挂战果链接或 KB 分析，也不足以立传。战果值得补进有故事的列传，没有人物故事或指挥依据的候选先留线索。已有依据的 FC 可以保留短传，按实际职责和已核经历写，不把零伤害、名字或空简介包装成性格故事；不按行数删人。高价值旗舰规则只决定料的红黑归类，不替代立传依据。

## 4. 构建与自查

开工的环境与离线基线按 `AGENTS.md` 第 6 节。新人物或缺快照时 `npm run fetch`；最后一次改动后 `git diff --check`、`npm run build`，不重复刷新齐全数据。

读 `_site/p/<ID>/index.html`：标题、每块料、锐评渲染正常，无残留 `:::`，句句接得上；核对原有料没有被误删、链接与当前事件对应。更换收录 ID 时清掉旧 ID 的生成页，再核互链，防止旧页面留在搜索索引里。

按 `docs/writing-review.md` 通读正文：逐处处理核查腔与自我否定，核对有无把能写的冲突退成待核事项、有无围绕此人的线索发挥。每处修订都要保留原有事料、来源立场和必要推测标记；删掉免责声明后仍像摘抄的，继续改写。

## 5. 汇报（不提交）

按 `AGENTS.md` 第 0 节简短报告缺口与验证状态；全仓失败必须说清，临时副本通过不算全仓完成。不提交、不推送，不给上线网址。
