# 添加／修订列传

开工先读 `AGENTS.md` 第2—6节，写作前读 `docs/writing-review.md`；查料时再读取材手册相应段落。

## 1. 对应人物

先读已有列传、本人素材与共享来源，按 `AGENTS.md` 第2节判断收录门槛；非CEO、非联盟重要管理者、非FC不能仅凭简介幽默、个人自嘲、普通聊天或KB立传，材料不足者归线索并同步索引与队列。已有列传默认增补，重写须按明确范围；保留原有主线、职责及红黑料。已有身份直接复用；新收录或身份冲突用 `npm run find -- "名字或链接"` 查ID、查重。无主号用本人小号；完全对不上归线索和备忘录。

## 2. 补料与写作

- 按 `docs/research-method.md` 复用来源、处理具体缺口；按其中“按增量安排下一步”先读具体事件与作者链，普通修订不自动联网。联网前先读手册对应段落，手册优先于个人记忆笔记。B站不按人名或外号逐人检索：先查 `docs/bilibili-uploaders.md`，只读名单已登记 UID、本人贴出的链接；UP取材先核空间“最新发布／最多播放”与合集，再按手册读候选，身份不因未读完而撤掉；未命中记“待板块扫描”，新发现靠板块批量扫描登记后反查。批量调查交给 `research-community`。
- 新人物按 `docs/person-template.md` 先写有效的同名列传，再建 `materials-<短名>.md`；收录后迁入旧线索、同步索引和备忘录。
- 写作要显著发挥：每块料按写作验收“发挥要显著”展开成一段完整的戏（一般四五句以上），只复述原帖或一两句加笑话的块要重写。讲人的行动、冲突和反差，来源交代一次后继续叙事；推测用“大概”等标记，不编事件、对话或战果；核查账留素材。战绩围绕自然人合并，保留综合KB与已核战役，不相加各号统计。
- 批量写作先验收少量代表人物，再扩批；不删原有料，不用套话补篇幅。

前两个作品候选质量较高时，按取材手册继续扩选并补足5个；不得以“最多5个”或首批读取上限为由在2个收尾。少选须有继续筛选后的实际依据，未读只记未完成。

## 3. 验收

环境、数据抓取与校验按 `AGENTS.md` 第6节。最终 `git diff --check`、`npm run build`，按写作验收页通读正文和 `_site/p/<ID>/index.html`。更换ID时清旧生成页、核互链。简短报缺口，改动留工作区，不提交或推送。

收录门槛（CEO、联盟重要管理者、FC可留短篇且不因故事少撤回；军团内部管理岗按普通成员算，只有一条分量不重的料时须先补料、补不到归线索；作者的作品互动算独立故事）按 `AGENTS.md` 第2节与写作验收，不在技能里另写。
