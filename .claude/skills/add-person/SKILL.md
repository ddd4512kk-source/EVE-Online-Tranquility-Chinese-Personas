# 添加 / 修订列传

先确认已读过仓库根目录的 `AGENTS.md`（特别是第 4 节写作规范），以及中文对照表 `docs/glossary.md`——英文术语、黑话必须按表里的社区说法翻译。

## 1. 收集输入

需要两样东西：

- **角色**：名字、EveWho 链接、zKillboard 链接或角色 ID 均可。
- **素材**：已有的事迹、黑历史、聊天记录、外号、中文名、对此人的评价等。

需要自行取材时，按 `docs/research-method.md` 操作：用中文关键词走百度搜索（`node scripts/research/baidu-search.mjs "某某 eve欧服吧"`），重点是贴吧 eve欧服吧；每人都跑一遍黑料关键词，并给每条料估分量。

缺角色对应时先查人物素材库和角色备忘录，补查链接；仍不明就登记具体疑问。找不到主号时可用已确认属于本人的小号。素材少也可以写，但**只写素材里有的**，不要编造。

自己取材时按 `docs/research-method.md` 的必查清单逐项做（游戏数据画像 → 本人论坛全部发帖 → 百度/360/必应 → B 站 → 其他），**不筛料**：找到的有出处的料全部写进去，模板的一红两黑不是配额。有出处的社区爆料可以直接用，不必等定论，写明来路即可（“据某某爆料”“圈内一说”）。

取材材料按人物归入 `docs/materials.md`；角色问题及待撰状态维护在 `docs/pending-characters.md`，不按取材轮次新建文档。完成列传后同步状态，材料直接写事实与来源，不记录素材提供者身份或对话过程。

## 2. 查 ID、查重

```bash
npm run find -- "<名字或链接>"
```

- 输出“已有列传：src/people/xxx.md” → 这是修订任务：读那个文件，在原文基础上增补，不要推倒重写，除非明确要求重写。
- 找不到角色 → 角色名须完全一致，确认拼写并登记待核对问题。

## 3. 撰写

新建 `src/people/<短名>.md`（小写字母/数字/连字符，如角色名 `Water Sky` → `water-sky.md`），从 `docs/person-template.md` 复制结构。

逐项决定：

- `cn_name`：素材里有社区中文名就填，没有就省略。
- `aliases`：素材里出现的外号。
- `epithet`：一句话锐评，≤25 字，要狠要好笑。这是目录页最显眼的文字，值得多想几版挑最好的。
- `tags`：先 `rg "^tags:" src/people/*.md` 看看已有标签，尽量复用。
- 正文：开篇叙事 → 若干 `::: 红料 标题` → 若干 `::: 黑料 标题` → `::: 评`。每条料一块，标题概括事件。

风格：戏谑、损而不恶，可点缀史书笔法。不提游戏内 NPC 势力与世界观背景（种族、NPC 大学、The Scope 等 NPC 军团）。素材里有现实隐私（真名、单位、住址、电话、照片）时，先确认是否允许公开。

## 4. 抓取与构建

```bash
npm run fetch
npm run build
```

构建报错会给出中文原因与行号，修好重来，直到成功。

## 5. 自查

读 `_site/p/<ID>/index.html`，确认：标题与中文名正确、红料黑料块都渲染了、锐评在文末、没有残留的 `:::`。

## 6. 提交上线

```bash
git add src/people/<文件>.md src/_data/characters/<ID>.json src/portraits/<ID>.jpg
git commit -m "添加列传：<名字>"     # 修订则用“修订列传：<名字>”
git push
```

推送前若没有明确授权，先问一句。

## 7. 汇报

用中文简短汇报：

- 写了谁、几条红料几条黑料、一句话锐评是什么；
- 网址：`https://ddd4512kk-source.github.io/EVE-Online-Tranquility-Chinese-Personas/p/<ID>/`（推送后 1–2 分钟生效）；
- 素材中你拿不准、标了“据传”或略去的部分。
