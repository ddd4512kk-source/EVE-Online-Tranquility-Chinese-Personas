# 添加／修订列传

开工先读 `AGENTS.md` 第2—6节，写作前读 `docs/writing-review.md`；查料时再读取材手册相应段落。

## 1. 对应人物

先读已有列传、本人素材与共享来源，按 `AGENTS.md` 第2节判断收录门槛；非CEO、非重要管理者、非FC不能仅凭简介幽默、个人自嘲、普通聊天或KB立传，材料不足者归线索并同步索引与队列。已有列传默认增补，重写须按明确范围；保留原有主线、职责及红黑料。已有身份直接复用；新收录或身份冲突用 `npm run find -- "名字或链接"` 查ID、查重。无主号用本人小号；完全对不上归线索和备忘录。

## 2. 补料与写作

- 按 `docs/research-method.md` 复用来源、处理具体缺口；按其中“按增量安排下一步”先读具体事件与作者链，普通修订不自动联网。批量调查交给 `research-community`。
- 新人物按 `docs/person-template.md` 先写有效的同名列传，再建 `materials-<短名>.md`；收录后迁入旧线索、同步索引和备忘录。
- 讲人的行动、冲突和反差，来源交代一次后继续叙事；推测用“大概”等标记，不编事件、对话或战果；核查账留素材。战绩围绕自然人合并，保留综合KB与已核战役，不相加各号统计。
- 批量写作先验收少量代表人物，再扩批；不删原有料，不用套话补篇幅。

## 3. 验收

环境、数据抓取与校验按 `AGENTS.md` 第6节。最终 `git diff --check`、`npm run build`，按写作验收页通读正文和 `_site/p/<ID>/index.html`。更换ID时清旧生成页、核互链。简短报缺口，改动留工作区，不提交或推送。

FC依据包括本人自称／带队自述及他人明确佐证，不要求Monitor。已对应作者的教学、持续创作与作品互动也按独立故事判断；明确作品入口待读时先补读，不把阅读缺口当作撤回结论。

重要管理者可按实际人事、招新、外交、战备等职责保留短篇，不限定CEO头衔；讲实际负责的事，不把普通联系人自动当重要管理；已核现役联盟执行军团中的本人角色按核心管理保留短篇，后续补实际事务，不额外等待CEO头衔。
