# 添加／修订战役

开工先读 `AGENTS.md` 第2—6节与 `docs/battle-template.md`，写作前读 `docs/writing-review.md`。

## 1. 立项

- 分档按各方总损失：100B–不足 400B 为中型，400B–不足 1T 为大型，1T 及以上为史诗；不足 100B 不立战役页，只写进人物列传。
- 先在 `docs/sources/` 的战役表、人物素材里找已有记录；同一场战斗只立一页。多日连打或同一星系的前后几战，各有独立战报口径、单场够分量时分开立页（如 M2-XFE 首战、第二战、突围）。
- 编组：同一星系几天内接连打的同一轮攻防，单场不足门槛或分量偏轻的，编成一页（如 Y-MPWL 2025-08-19、08-21、08-24 三场）。`start`／`end` 覆盖全程，总损失为各场之和，`loss_source` 按时间列各场战报，各场时间窗与损失写素材。开工前查已有战役页的星系与日期：已编进一组的单场不另立页，要补就补进那一组；同一星系日期重叠的两页构建会失败。
- 战役名：中文社区叫法优先，星系有通行中文名的用中文（Obe 欧贝、Taff 塔夫），低安星系在标题中必须用游戏内中文名或通行中文名，表内缺名先查 CCP ESI 中文资料并补齐，不自行音译；正文与人物列传里的战役链接文字同步改中文，英文保留在别名与来源原题；00 区字母数字名保留原名（M2-XFE）；`systems` 写英文名，中文名登记在 `src/_data/systemNames.js`，页面显示“欧贝（Obe）”；标题是野史回目，要有戏：抓本场最出名的一点、反差或笑柄，写成一句话（“欧贝钓出三百泰坦”“塔夫春晚，FRT 买单”），不套“某某之战”“某某战役”；社区已有响亮叫法（如“M2-XFE 大屠杀”）就用。平实的地名叫法、英文名放 `aliases`，起名依据记素材。
- 短名用 `<星系或通称>-<年份>`，小写字母、数字、连字符，如 `obe-2026`。

## 2. 口径与阵营

- 首选 br.evetools 完整战报（`br/<ID>`，或 `related/<星系ID>/<时间>`）；killmail.app 完整战报（`br/<ID>`）同样可用，两家同场战报可一起写，KM 按 ID 去重、分队取有分队的那份。`loss_source` 全是这两家战报时就是**快照战役**：`npm run fetch` 抓战报存成 `br.json`（勿手改），全场与各方人数、损失、记录条数、华人军团人数、参战人物都由它算，front matter 不写任何数字。战报混进了前后别的场次，用 `window` 截时段（UTC）；`systems` 也会筛星系。改了来源、星系或时间窗，下次 fetch／build 自动重抓。
- 没有这两家完整战报、要用 CCP 新闻、WarBeacon、EVE-KILL 或论坛自报口径时是**手填战役**，见下文“手填战役”。只有 KM 求和时写下限，并设 `loss_is_lower_bound: true`，让目录和页面显示“至少”。
- 阵营：`sides` 写 2–4 方的社区叫法（“FRT 及友军”“十国联军”）和点名联盟 `alliances`（写联盟 ID，无联盟的军团写军团 ID，用 `npm run find -- "全名"` 查；名字由全站名称表 `src/_data/entityNames.json` 显示，表里没有的 `npm run fetch` 向 ESI 补）。快照按点名联盟认领战报作者分的队伍：一队里点名的联盟都在同一方，整队归这方；一队横跨两方的不采用。战报没分队时，未点名的组织按交火推断。归不了方的自动并成“第三方”；要给第三方写正文或点名联盟，就写一方 `name: 第三方`，点名给第三方的联盟只把自己摘出分队。点名的 ID 不在本场战报里会报错，改 ID 或删掉。
- 点名联盟要看战报分队：把某联盟点给甲方，它却在战报里和乙方同队，整队就会失去归属。先读战报分队再点名，映射依据写素材。
- 联盟名会被新联盟重用，同名时认准本场战报里出场的那个 ID。
- `tags` 写三五个供目录筛选：地带（低安、00区）、战型（泰坦战、无畏战）、主要势力（FRT、INIT、Goons 等社区简称）；规模档位自动加，不必写。

## 3. 人物与华人军团

- 快照战役：收录号或本人列传 `alts` 里的小号在本场战报出场，就自动认出、落到其所在一方，人物页自动反链；主号小号算一人。战役页不手列 `people`（写了会报错）：小号没认出，把小号 ID 补进本人列传 `alts`；人算错一方，是其所在组织归错了，改点名联盟。
- 华人军团：在 `src/_data/entityNames.json` 里给该军团加 `"chinese": true`，全站快照战役自动列出它在各场的人数，页面按人数排在所属一方下，战役 front matter 不写。本场战报里出场、还没标记的华人军团补上标记；非华人军团（如 GoonWaffe）里只有个别华人成员的不标，人物照样由收录号自动认出。
- 人物列传里引用本场战报网址处，改链到 `../../battles/<短名>/`；KM 链接保留。

## 手填战役

- `total_loss`（B）必填，`pilots` 可选；每方填参战角色数 `pilots`、损失金额 `loss`（B）、损失记录条数 `loss_count`，目录和详情逐方显示，全场总计不能替代。无现成汇总时在同一窗口、星系内按 KM ID 去重，人数取本方攻击者与受害者角色 ID 并集，金额和记录条数按受害方统计。记录条数含胶囊、建筑，不等于纯船体数。
- 确实取不到的项显式写 `null`，并填 `stats_note` 说明来源缺口、已查范围和续查入口；页面显示“待补”，不得漏填、用总数代替、拿样本／峰值冒充全场，或用 0 代表未知。
- 各方 `corps` 写 `{ id, pilots? }`（军团 ID），`people` 手列本方全部已收录人物，逐张比对 KM 落方；归不进任何一方的人不填，素材写明原因。
- 联盟、军团 ID 不在名称表里的，`npm run fetch` 向 ESI 查名字补进去；ESI 也查不到会报错，改 ID 即可。

## 4. 写作

- 按模板：开篇交代起因、各方、规模与账单落在谁身上，再按 `## 阵营名` 分节写各方华人，最后 `::: 评`。
- 每方挑影响战局或最有戏的人写成红料／黑料块：指挥、动员、名场面、重大损失、阵前跳槽。每块按写作验收展开成一段戏，不念参战名单——名单由页面自动列出。
- 个人船型、逐号统计写在本人列传；战役页只取能讲成故事的部分。0 伤害显示不作素材；监视者驾驶员按 FC 写，不提船型。
- 立场中立；双方都是华人时两边一样损。

## 5. 验收

`npm run fetch`（快照战役抓战报）、`npm run check`、`git diff --check`、`npm run build`，确认目录与详情每方均显示人数、金额、损失计数；快照战役核对算出的分方数字与战报网页大致相符、自动第三方没吞掉主力，手填战役缺项有明确待补及素材续查依据。通读 `_site/battles/<短名>/index.html` 与受影响的人物页。素材写 `materials-<短名>.md`，同步 `docs/materials.md`。改动留工作区，不提交或推送。
