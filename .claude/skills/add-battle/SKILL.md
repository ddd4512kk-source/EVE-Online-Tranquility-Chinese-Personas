# 添加／修订战役

读取 `docs/rules-battle.md`（含人物归因、叙事与高潮、文风与素材）和 `docs/terminology.md`，字段与口径读 `docs/battle-template.md`，成稿读 `docs/battle-review.md`。涉及新人物收录转 `add-person`。

1. 用 `npm run materials -- "星系或战役名"` 定位已有战役与来源，再在相关战役表、人物素材中查重，核对星系、日期和编组范围；按战役规则决定单场或编组。跨篇复查或修改分方功能，先按[增量复查](../../../docs/review-workflow.md)筛 `battle-attribution` 卡片与变更影响，不整批加载所有战役正文。标题与短名按战役模板。
2. 选择战报来源与窗口，按 `docs/research-battle.md` 读取网页完整分队，与当事人复盘及逐舰记录交叉核对后点名归方，把完整映射、冲突与采用理由、逐方核对结果写进素材；执行战役规则的分方交叉核对要求。配置统一存于`<短名>.json`的`battle`，归方只用`organizations`、主标单独用`emblem`；Markdown只留正文。快照用`npm run fetch`抓入同一JSON的`br`，刷新只替换`br`；手填按模板逐方核统计。联盟重名时认本场 ID。
3. 对照算出的各方、自动参战联盟、人物及华人军团。联盟名单按模板由历史快照汇总，展示与名称补取遵守战役规则的10人／华人军团条件，不逐场手补或用当前联盟回填。小号未识别时补本人 `<ID>-id.json` 的 `identity.alts`，人物落错方时改组织归属；按战役规则标记华人军团。人物列传引用本场战报处改链到战役页，KM 链接保留。
4. 按战役规则的[素材](../../../docs/rules-battle.md#素材)一节取材：检索并读完参战人物的列传与素材、同期相邻战役和相关视频，事件与出处记进本场素材。只有战报数字时不进下一步。
5. 按时间线写这场仗，最精彩的场面放进高潮块；修订旧稿时把红料、黑料块改进时间线，按战役模板整理相关视频，素材存 `materials-<短名>.json`；碰到 EVE 相关的 B站 UP 或视频，把链接写进素材，未入档时 `check` 会报错并给出命令。只更新仍有待办的原队列，材料目录按需生成。
6. 按 `docs/battle-review.md` 核读正文、目录及受影响人物；生成页与现稿一致才通读，否则报告未验证，并按 AGENTS.md 做定向校验。
7. 能开子代理时，正文定稿后把第 6 步交给新开的 `battle-reviewer` 子代理（模型和强度已配好：Claude Code 为 Sonnet 中等，Codex 为 Luna 高，不另行指定），只交代短名、本次改动文件和范围，说明是否改了分方，不转述主会话对质量的自评，也不要求通读规则文档。子代理只做格式、术语、链接等机械修正，分方、数字和正文缺口交回主会话。缺口只是小修时，主会话改完直接交付，不再动用子代理；实质重写才把改动位置发回同一子代理续审，不另开新子代理从头读起。
