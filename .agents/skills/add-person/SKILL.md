# 添加／修订列传

先判断本次是否在写人物正文。雷达图、九宫格阵营等独立组件的增删改不属于本技能的列传写作流程，即使数据存在人物档案，也不进入下面第 1–5 步，不调用 person-reviewer；阵营按[九宫格阵营](../../../docs/person-alignment.md)判定；先按[列传六维品评](../../../docs/person-radar.md)核对已有战神底线及大亨交叉复核规则，再按[开发与验证的组件边界](../../../docs/development.md#展示组件与样例的执行边界)完成本次展示。只改数据适配、格式或展示字段时只读相关字段约定并做定向验证，不因档案指纹变化启动整篇复审。

确实新增或实质修改人物正文时，按 AGENTS.md 的任务表读取 `docs/rules-person.md`、`docs/terminology.md` 和 `docs/materials-person.md`；写作前读 `docs/person-review.md` 和 `docs/person-template.md`。已有上下文不重复加载。

1. 用 `npm run materials -- "人名或角色ID"` 定位已有列传、本人素材和共享来源，再按需读正文。已有身份先查 `node scripts/person-identity.mjs <短名或角色ID>` 统一档案（字段见 `docs/person-identity.md`），直接复用；新收录或身份冲突用 `npm run find -- "名字或链接"` 查 ID、查重。已有列传默认增补，重写须按明确范围，保留原有主线、职责及红黑料。
2. 先处理具体事件与作者链的缺口。按功能修订先用[增量复查](../../../docs/review-workflow.md)读取对象卡片、相关段落与失效结论；新收录和战斗补漏按列传验收核调查覆盖，不以已有独立故事代替游戏画像。需要取材时读 `docs/research-person.md`，联网再读 `docs/research-method.md` 对应入口；普通修订不自动联网。批量调查转 `research-community`。碰到 EVE 相关的 B站 UP 或视频，把链接写进素材；未入档时 `check` 会报错并给出命令。
3. 按模板建立只含正文的同名列传、`<ID>-id.json` 档案与素材文件；收录时迁入旧线索，更新备忘录及原队列；材料目录按需生成，不再维护全员索引。按列传验收完成正文。新收录同时按[六维品评的新收录完成要求](../../../docs/person-radar.md#新收录完成要求)完成评分并单独校验，缺评分不得报告创建完成；同时按[九宫格阵营](../../../docs/person-alignment.md)在档案 `person.alignment` 定下阵营，改写既有人物时若尚无阵营顺手补定。组件结果不交给正文评审代验。
4. 新收录、重写或实质补写的正文定稿后按[开发与验证](../../../docs/development.md)做本次范围检查；有与现稿一致的生成页时通读，否则核正文并报告生成页未验证，换 ID 时另核互链。按[增量复查](../../../docs/review-workflow.md)用 `review template` 生成草稿（输出含校验约束、格式与锚点，完整读取，不翻脚本源码），逐项核读后登记 `combat`、`writing-depth`，分别运行 `review verify`。只有影响该项结论的正文、身份、战绩或素材变动才重登；独立组件与纯展示变动不重登。模板或验证受无关故障阻挡时报告，不为本次交付追查或改动无关规则。新收录、重写及实质补写两项缺项、待补或失效不得当作复审通过；链接、错字等轻微修订可复用有效结论。
5. 能开子代理时，正文定稿后把第 4 步交给新开的 `person-reviewer` 子代理（模型和强度已配好：Claude Code 为 Sonnet 中等，Codex 为 Luna 高，不另行指定），只交代短名、角色 ID、本次改动文件和补写范围，不转述主会话对质量的自评，也不要求通读规则文档。子代理只做格式、术语、链接等机械修正，复查按现稿独立判断；正文缺口记 `needs-work` 并交回主会话，不为交付凑 `reviewed`，也不联网取材或改其他人物。主会话读其报告并补缺口。缺口只是小修（措辞、个别事实、引语核对、不改主线的段落补写）时，主会话改完直接更新草稿重登，不再动用子代理；实质重写才把改动位置发回同一子代理续审重登，不另开新子代理从头读起。复跑 `verify` 确认后交付。
