# 社区取材与批量查漏

读取 `docs/content-rules.md` 第 2、3、6 节及 `docs/research-method.md` 本次入口段落；收录、归因、平台读取和请求规则只在这些文档维护。

1. 用 `npm run materials -- "本次对象"` 定位已有材料，大榜单按[材料查询](../../../docs/research-method.md#本地材料查询)筛选分页读取。跨人物／战役查漏、改规则后的复查先走[增量复查](../../../docs/review-workflow.md)：筛候选、读卡片与必要段落，保存本项人工结论，不整批加载全文或凭信号判完成。复用素材、缓存和排除记录，明确对象与时间窗。沿唯一冻结队列续跑，分别记录取得、核读、身份对应、归档、入文和下一步；新增互链单列，不重扫成功来源。
2. 按取材手册“按增量安排下一步”选分支：B站用材料查询定位 UID 档案，再按档案中的 BV 补缺口；新发现沿取材手册的扫描队列；贴吧先查`docs/tieba/`的逐帖JSON和`scans.json`，人工状态只在这里维护，不另建Markdown／TSV处理队列，再追作者与回复网络；战役从社区复盘找 BR，再核窗口并对照人物与小号；军团／FC调查区分榜单月份、CEO核对日和任职期，先核接口结构再抽取，CEO对照不能代替成员榜。
3. 归档后重读新增段落，提炼事件、各方说法与可展开的冲突，明确新增同人或职责依据。共享事件只存一份，按内容规则处理线索、排除记录和过期队列。
4. 达到收录条件后转 `add-person`，新增或修订战役转 `add-battle`。更新队列并按 AGENTS.md 校验；取得数据、构建通过不等于调查完成。

军团榜与跨团角色调查先查[军团档案](../../../docs/corporations/README.md)，不续写旧日期命名ledger。榜单固定Top 100，历史月份优先；已有all-time只作hint，不刷新，旧前50及缺失范围如实保留。不维护调查批次，结构调整不触发联网或补查。
