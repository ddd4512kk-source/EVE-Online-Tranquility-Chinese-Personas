# 网站设计约束

由 `AGENTS.md` 第 4 节要求：改布局、样式、前端交互时读取。

- **纯静态**：无数据库、后端、运行时 API；游戏数据是一次性快照。
- **零外部资源**：不引用 CDN、Google Fonts、统计脚本；无衬线与等宽用系统字体栈。衬线字（`var(--serif)`：正文与各级标题）本机有思源宋体就用本机，否则用站内自托管的 Noto Serif SC 400、700 两个字重切片（SIL OFL，`src/assets/fonts/serif/` 与 `src/assets/css/fonts.css`），浏览器按 `unicode-range` 只下载当页用到的切片，长篇列传首次打开约多下载 0.5–1 MB，之后走缓存；切片覆盖本站已用字与 GB2312，新出现的生僻字回退系统宋体，积累多了用 `scripts/make-fonts.mjs` 重新生成（一次性工具，不接入构建）。只有 400、700 两档，其他字重就近取用。唯一例外：页眉的 hits.sh 访问计数徽章（一张图，全站共用一个计数，地址在 `src/_data/site.js`）。
- **移动优先**：16px 页边距，任何宽度无横向滚动。改完在 390px 与 1366px、深色与浅色下检查，无 JS 报错。
- **深浅双色**：默认深空墨底，浅色模式为宣纸底；默认跟随系统，页眉日／月按钮可手动切换（`html[data-theme]`，存 `localStorage`，无 JS 时按钮隐藏）。新样式只用 `site.css` 的 CSS 变量；浅色取值在 `site.css` 里有两段（跟随系统、手动选定），改一段必须同步另一段。
- **无 JS 也能读**：JS 只做增强（筛选、排序、随机、搜索、标签折叠）。
- **图片缓存**：`src/sw.js`（Service Worker）把头像、战徽、字体存在读者本地，先显示本地的、后台核对更新；只经手这三类同站文件，不缓存网页、样式和脚本。出问题时按文件头注释换成自我注销版即可停用。
- **视觉**：史书列传 × 深空。衬线正文；`epithet` 与 `::: 评` 用朱砂色（朱批）；红料红边框“红”字徽记，黑料墨块“黑”字徽记；站印红底白字“野”，内衬白圈、微斜如盖章。全站铺一层固定氛围：深色为左上朱、右上与底部青的天幕辉光加稀疏星点，浅色为同色淡光加宣纸纹理（内联 SVG，无外部图）。面板（卡片、`bio-facts`、翻页、战役行与阵营卡）用 `--surface` 渐变底与 `--panel-shadow` 立体阴影，悬停加金边微光；大标题与列传名用 `--title-ink` 墨金渐变字，`intro` 标题下一道朱接金的短线；大头像与战役大战徽用细线、留白、金边三层装裱；战役大数字带同色微光（浅色不发光）。氛围与质感只用 `site.css` 变量，深浅两套取值同步。
- **首页**：按创号时间排序（可倒序、随机），连续网格，每年首张卡挂年份签；标签栏单选同步 `?t=`，筛选框同步 `?f=`。列传页网址 `/p/<角色ID>/`。
- **板块**：页眉导航按 `src/_data/sections.js` 依次列板块，再接搜索、随机、深浅切换（标签在列传首页标签栏筛选，`/tags/` 页保留但不进导航）；板块尚无内容时不进导航。战役目录 `/battles/`，战役页 `/battles/<短名>/`，默认按开打日期倒序，可切时间新旧、按损失、随机排序，标签栏单选（规模档位在前）同步 `?t=`；一场一行，标题与总损失、参战人数用大字（总损失朱砂、人数金色），行内并排列各方阵营（主要联盟、参战角色数、损失金额、损失记录条数、华人军团与收录人数）。战役页标题下先列总损失、参战角色、交战方三个大数字，再接时间地点（星系有中文名的写“欧贝（Obe）”，名表在 `src/_data/systemNames.js`）、阵营卡片（每方突出显示参战角色数、损失金额、损失记录条数，再列损失占比条、联盟、华人军团、人物；缺数保留标签并显示“待补”），再接正文。联盟、军团名一律链到 EveWho，与列传页一致；战役页面显示游戏内缩写，悬停保留全名。详情页的联盟、华人军团和人物名单超过一行时显示“展开／收起”，各名单独立控制，无 JS 时全部可读。史诗用朱砂实底徽记，大型用金边徽记，中型用灰边徽记。新板块沿用卡片、`bio-facts`、`prose`、朱批与翻页组件，网址用 `/<板块>/<短名>/`，不改动已有网址。全文搜索按 `板块` 筛选。
- 简单胜于花哨，不引入运行时依赖。

- **小规模第三方不展示**：全站所有战役中，第三方合计参战不足 30 人时，目录与详情页均不单独显示其阵营、人数、损失、军团或人物，不另写第三方正文段落，也不计入页面显示的交战方数量。原始记录、全场总人数与总损失及人物战役关联照常保留；第三方达到 30 人或人数未知时仍显示。

- 战役相关视频放在正文后，沿用 `prose` 排版，展示标题链接、UP 主及介绍；无视频时隐藏，使用原站链接，不嵌入播放器、远程封面或新增脚本。

## 战役对阵战徽

- 目录与详情共用 `src/_includes/battle-emblem.njk`，分别显示小、大尺寸。“刀口对撞”：两方主标放大出血、按反对角线裁成两半，左半朱砂底光、右半青色底光，只区分两方；三、四方平分画面。各块之间的刀口颜色即档位（史诗朱砂、大型金、中型灰），刀口两侧带一道微光。不按损失比例偏移刀口，不表示胜负。深浅色跟随全站变量，窄屏缩小。
- 阵营配色与战徽一致：第一方朱砂、第二方青色、其余灰，用于目录阵营栏左边、详情阵营卡左边与损失占比条；只区分阵营，不表示胜负。目录每行右侧以前两方主标虚化淡出作水印，顶边一道档位色细线（史诗朱砂并带淡朱辉光、大型金、中型灰），阵营栏上方一条各方损失占比细带；详情页头同样以两方主标作大水印、四周淡出，大数字之间以竖线分隔。水印纯装饰，不出横向滚动。
- 从既有 `sides` 中按原顺序取最多四个主要阵营，不取“第三方”；每方使用 `alliances` 第一项的原图标，每方一枚主标，不按当前联盟归属重分阵营。三方、四方自动分格；无组织时用阵营前两字。
- 图标按组织 ID 共用，放在 `src/assets/emblems/`；来源为 [CCP Image Server](https://developers.eveonline.com/docs/services/image-server/) 的 128px PNG。使用获取时的图标，不声称复原历史旗帜；`alliance-<ID>.png` 与 `corporation-<ID>.png` 分开，防止混淆。
- 新战役沿用已有阵营字段即可，无需单独制图。`npm run fetch:battle-logos` 补齐缺失图标，已接入 fetch 与 build；缓存齐全时不联网，获取失败会阻止构建，不发布破图。若需要突出另一主要组织，核对阵营后调整对应 `alliances` 顺序。
