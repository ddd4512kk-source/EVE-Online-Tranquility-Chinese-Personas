# 网站设计约束

由根目录与 `src/` 指令要求：改布局、样式、前端交互时读取。

- **纯静态**：无数据库、后端、运行时 API；游戏数据是一次性快照。
- **零外部资源**：不引用 CDN、Google Fonts、统计脚本；无衬线与等宽用系统字体栈。衬线字（`var(--serif)`：正文与各级标题）本机有思源宋体就用本机，否则用站内自托管的 Noto Serif SC 400、700 两个字重切片（SIL OFL，`src/assets/fonts/serif/` 与 `src/assets/css/fonts.css`），浏览器按 `unicode-range` 只下载当页用到的切片，长篇列传首次打开约多下载 0.5–1 MB，之后走缓存；切片覆盖本站已用字与 GB2312，新出现的生僻字回退系统宋体，积累多了用 `scripts/make-fonts.mjs` 重新生成（一次性工具，不接入构建）。只有 400、700 两档，其他字重就近取用。唯一例外：页眉的 hits.sh 访问计数徽章（一张图，全站共用一个计数，地址在 `src/_data/site.js`）。
- **移动优先**：16px 页边距，任何宽度无横向滚动。改完在 390px 与 1366px、深色与浅色下检查，无 JS 报错。
- **深浅双色**：默认关灯（深空墨底），不跟随系统；浅色模式为压暗一档的旧宣纸底，卡片不用近白；页眉日／月按钮可手动切换（`html[data-theme]`，存 `localStorage`，无 JS 时按钮隐藏）。新样式只用 `site.css` 的 CSS 变量；浅色取值只在 `site.css` 的 `:root[data-theme="light"]` 一段。
- **无 JS 也能读**：JS 只做增强（筛选、排序、随机、搜索、标签折叠、列传页小号超过两行折叠）。
- **图片缓存**：`src/sw.js`（Service Worker）把头像、战徽、字体存在读者本地，先显示本地的、后台核对更新；只经手这三类同站文件，不缓存网页、样式和脚本。出问题时按文件头注释换成自我注销版即可停用。
- **视觉**：史书列传 × 深空。衬线正文；`epithet` 与 `::: 评` 用朱砂色（朱批）；红料红边框“红”字徽记，黑料墨块“黑”字徽记；战役 `::: 高潮` 金边淡金底、金底“高潮”徽记；站印红底白字“野”，内衬白圈、微斜如盖章。全站铺一层固定氛围：深色为左上朱、右上与底部青的天幕辉光加稀疏星点，浅色为同色淡光加宣纸纹理（内联 SVG，无外部图）。面板（卡片、`bio-facts`、翻页、战役行与阵营卡）用 `--surface` 渐变底与 `--panel-shadow` 立体阴影，悬停加金边微光；大标题与列传名用 `--title-ink` 墨金渐变字，`intro` 标题下一道朱接金的短线；大头像用细线、留白、金边三层装裱；战役大数字带同色微光（浅色不发光）。氛围与质感只用 `site.css` 变量，深浅两套取值同步。
- **外部链接**：站点内链接（`/p/`、`/battles/`、`/corps/`、`/tags/`、`/glossary/` 等）在当前页面跳转；任何导向外部的链接（`http://`、`https://`，如 EveWho、zKillboard、Dotlan、Bilibili、GitHub、问卷等）必须带有 `target="_blank" rel="noopener noreferrer"`，一律以新窗口或新标签页打开，不得顶掉当前浏览页面。
- **首页**：按创号时间排序（可倒序、按最近更新、六维、随机），连续网格；卡片不显示创号日期，只在列传页资料栏写；筛选区沿用军团目录的分组行：首行搜索框、随机和“排序”组，次行“标签”组，都用标签胶囊。标签可多选，取交集，“全部”即清空，同步可重复的 `?t=`；筛选框同步 `?f=`。排序胶囊为创号、更新与六维，六维胶囊各带本维颜色（未选描边、选中填色），再点当前项切换方向，箭头随之变；非默认排序同步 `?sort=<键>`，反向另加 `?rev=1`。六维首点由高到低，同档先比其余五维阶位之和，再按创号先后，待考不论方向都排最后。各目录工具栏不放“全文搜索”链接，全文搜索只走页眉入口。列传页网址 `/p/<角色ID>/`。
- **板块**：页眉导航按 `src/_data/sections.js` 依次列板块，再接搜索、深浅切换（导航字加粗，列传金、战役蓝、军团朱砂，色取主题变量，深浅色各有对应值）（标签在列传首页标签栏筛选，`/tags/` 页保留但不进导航）；板块尚无内容时不进导航。战役目录 `/battles/`，战役页 `/battles/<短名>/`，支持即时文字检索（同步 `?f=`），默认按开打日期倒序并带年份分章头，可切时间新旧、随机排序；筛选沿用军团目录的分组行：首行为检索框、随机、排序（时间新旧）与规模，次行战斗类型与地带，参战联盟单独一行且长列表可折叠，规模标签沿用徽记色（史诗朱砂、大型金、中型灰），战斗类型标签超旗战紫、旗舰战蓝、常规战青，各组带“全部”，组内单选、跨组取交集，同步可重复的 `?t=`，无 JS 时全部可读。目录采用杂志 Bento 网格：史诗战役横跨整行（左 16:9 头图、右标题与大字数据），大型与中型在桌面端双栏并排（单数收尾卡自动横向铺满整行以消除半行空白），卡片均带档位标、时间星系、视频计数、标题、朱批点评、“甲方 对 乙方”及斜切拔河损失条；各方明细只放详情页。战役页顶部为返回目录与原始战报外链，主体为通栏一体式战策舞台：上半部在桌面端左右分屏（左侧完整 16:9 头图绝不压字遮挡封面花字，右侧陈列档位标、时间、Dotlan 星系链接、标题、别名、朱批点评、各方总损失与参战角色等核心大数字及分类／联盟标签；交战方仅在三方及以上时单列），中腰横贯全场战损占比拔河条与总损失记录数，下半部对接交战各方对称账本（每方配主标小徽章，突出参战角色数、随本方配色的损失金额、损失记录条数与占比条，再依次列列传人物、华人军团、参战联盟／主要组织；三方参战时第三方横跨底栏，缺数保留标签并显示“待补”）。舞台之下、正文之前接“相关视频”多视角视频区，正文与底部翻页保持居中阅读宽度。联盟、军团名一律链到 EveWho，与列传页一致；战役页面显示游戏内缩写，悬停保留全名。列传目录卡片与列传页的所属只写军团全名加缩写、联盟只写缩写（悬停看全名，无缩写才写全名），已离开时“（年月 离开）”整体不拆开，放得下就接在同一行，放不下才整体换行。目录卡片里军团名连同两个缩写最多占两行，军团名过长时以省略号截断（悬停看全名），缩写始终完整。详情页的标签、联盟、华人军团和人物名单超过一行时显示“展开／收起”，各名单独立控制，无 JS 时全部可读。史诗用朱砂实底徽记，大型用金实底徽记，中型用灰边徽记。新板块沿用卡片、`bio-facts`、`prose`、朱批与翻页组件，网址用 `/<板块>/<短名>/`，不改动已有网址。全文搜索按 `板块` 筛选。军团目录 `/corps/`，军团页 `/corps/<短名>/`，视觉走浮夸商业招商风格，按 `corp.style` 区分视觉主题（取值见[军团志模板](corp-template.md)，不印自创假头衔；目录卡片顶部是一块实色招牌门头，只放联盟、区域与状态，流派靠门头下沿的大轮廓——斜切、台阶、吊坠、锯齿、弧线、书签等——与战徽框形状区分，不在门头里压缩铺纹样；正文区素底，不铺底纹或水印压字，宣传语完整显示不截断），目录卡片与详情页公司卡均以装甲/HP 横条展示三项 0–100 印象指数（**武德**、**含神量**、**声望**）。目录为一整块网格，沿用列传的筛选框与随机，默认按武德排序（数值相同时按 zKB 近期榜排名垫底），可切含神量、声望、创立正序／倒序、随机；状态（活跃·招新中、活跃·未见招新、已沉寂、全部）、区域（高安、低安、00、虫洞、波赫文）与联盟各一排单选标签，同步 `?f=`、`?s=`、`?z=`、`?a=`、`?sort=`。默认只显示活跃·招新中，输入筛选词或选区域、联盟而未动状态时放开到全部；无 JS 时按创立时间全部可读。卡片写联盟与区域、状态标、宣传语、三维血条及创立年份、人数、zKB 击杀数与近期榜排名。军团页公司路演卡含规模、战绩、排位、区域四大指标格、三维血条与招新专线横幅，其后自动接列传中人（现任 CEO、现属成员、曾属成员、有过交集，名人在前），正文后自动接参战录（本团至少 3 人出场的战役页），两者默认折叠，无 JS 也能展开。
- **动态状态与人物标记**：判定只在 `scripts/activity.mjs`，构建时按快照计算：人物所有角色最晚击杀距快照 12 个月内为活跃，否则沉寂，无快照不标；主号与全部小号累计参与击杀总价值满 10 万亿 ISK，或按主号创号至最晚击杀（至少按 2 年折算）年均满 1.5 万亿 ISK 为战神；已确认本人的 B 站账号下按 BV 去重后播放量满 3000 的 EVE 视频不少于 10 条为 UP 主（数据由 `src/_data/bilibiliPeople.js` 汇总）；名人、大亨、神人不靠计算，名单与一句话理由分别在 `src/_data/famousPeople.js`、`src/_data/tycoonPeople.js`、`src/_data/shenrenPeople.js`，标准见[列传规则](rules-person.md#名人与特殊标记)；军团击杀 3 个月内，且 2 年内有招新帖（不看简介是否写仅限邀请），或没有帖子但简介写明招新且不是仅限邀请，为招新；击杀或招新帖 3 个月内为活跃，但 ESI 在册人数不足 21 的军团击杀不算数；区域优先手工指定，否则按 zKB 击杀分布取占比满四分之一的地带，近期不足 20 杀退回历史累计。活跃是绿环呼吸加脉冲灯，沉寂是头像褪色加灰光慢飘，招新是蓝色声呐，军团战徽另压活跃、招新、沉寂小标签并走扫光；名人是金光斜扫加“名”字方印，其余四项不用方块字印，且绝不遮挡头像五官：战神移至姓名旁配朱砂双刃准星击杀勋章（`src/_includes/wargod-insignia.njk`）并加卡片左侧朱砂战纹，大亨、神人、UP 主则在外框边缘挂载（`src/_includes/person-marks.njk`）——大亨是鎏金双线边框加底部外缘重工齿轮 × 飞翼金砖星币托座与浮金星芒，神人是头像微歪加头顶断裂电弧神环与太阳穴旁跳动的“？！”脑电波，UP 主是头像左下外缘粉红 B 站双天线小电视挂件；各项理由或统计写在悬停提示和列传页状态栏，各居一方、互不遮挡，可多项并存。只动透明度和位移；减少动效时静止，滚出视口时暂停。活跃、沉寂、名人、战神、大亨、神人、UP 主进首页标签栏筛选。
- 简单胜于花哨，不引入运行时依赖。
- **人物雷达图**：按[独立组件边界](person-radar.md#组件边界)设计，在资料面板之后、正文之前按需展示，组件增删不改变主列传。神力居顶并用朱砂色突出，图旁给出大号分数、档名和趣味短评。缺数不填零，不计综合分；尺度与展示约定只维护于[六维品评](person-radar.md)。目录卡片在头像列底部压一枚无字小雷达，所有卡片尺寸一致、与同排卡片底线对齐，只示轮廓与朱砂神力顶点，不加维度名、档位或任何新文字；无组件的列传与卡片保持原布局。

- **小规模第三方不展示**：全站所有战役中，第三方合计参战不足 30 人时，目录与详情页均不单独显示其阵营、人数、损失、军团或人物，不另写第三方正文段落，也不计入页面显示的交战方数量。原始记录、全场总人数与总损失及人物战役关联照常保留；第三方达到 30 人或人数未知时仍显示。

- 战役“相关视频”放在战策舞台之后、正文之前，按部数自适应排版：单部为横贯双栏导读卡，两部为对称双栏，三部及以上为左主推 POV 01 加右侧双层叠放 POV 02／03，超出三部的其余视角由抽屉按钮展开（无 JS 时全部展开可读）；无视频时隐藏，使用原站链接，不嵌入播放器、远程封面或新增脚本；战役头图的封面裁切存本站。

## 战役头图与对阵战徽

- 战役有视频封面（`battle.cover`）时用它作头图，居中裁成 16:9 存本站 `src/assets/emblems/cover-<短名>.webp`，宽不超过 960px、不放大，页面不在封面上压字，完整保留原图与精修花字；无封面才用下述深空档案图版，比例相同，卡片对齐。
- 目录与详情共用 `src/_includes/battle-emblem.njk`，纯装饰，阵营文字另有。无封面战役采用深空战术推演档案图版（`battle-archive-plate`）：底衬首要星系名幽灵水印与精密战术微网格，中央各阵营主标收进微光切角徽记框，配阵营名称，中间贯穿极细的战术刻度标尺与 VS 徽记，底部带档案标记；保证联盟图标清晰、克制、耐看，彻底摆脱低质感雷达大头贴风格。
- 阵营配色与战徽一致：第一方朱砂、第二方青色、其余灰，用于详情阵营卡顶边、本方损失金额与损失占比条；只区分阵营，不表示胜负。目录卡与详情战策舞台的边线用档位色（史诗朱砂并带淡朱辉光、大型金、中型灰），大数字之间以竖线分隔。
- 从既有 `sides` 中按原顺序取最多四个主要阵营，不取“第三方”；每方使用同名战役JSON中`battle.sides[].emblem`（计算结果中的`emblemOrganization`）指定的原图标，每方一枚主标，不按当前联盟归属重分阵营。联盟参与名单独立从历史快照汇总，不用名单排序改变主标。三方、四方自动分格；无组织时用阵营前两字。
- 图标按组织 ID 共用，放在 `src/assets/emblems/`；来源为 [CCP Image Server](https://developers.eveonline.com/docs/services/image-server/) 的 128px PNG。使用获取时的图标，不声称复原历史旗帜；`alliance-<ID>.png` 与 `corporation-<ID>.png` 分开，防止混淆。
- 新战役沿用已有阵营字段即可，无需单独制图。`npm run fetch:battle-logos` 补齐缺失图标，已接入 fetch 与 build；缓存齐全时不联网，获取失败会阻止构建，不发布破图。若需要突出另一主要组织，核对阵营后修改该方`emblem`，且须属于本方`organizations`。
