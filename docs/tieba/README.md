# 贴吧处理档案

本目录是贴吧发现、取得、人工阅读与后续处理状态的唯一正式入口。每帖一个`<帖号>.json`，同一帖子从旧库、高回复、互链或新帖扫描多次发现时仍只保留一份。`scans.json`记录扫描顺序、覆盖、原始冻结批次及迁移来源，不维护另一张人工状态表。

```sh
node scripts/tieba-archive.mjs list --status unread --limit 10
node scripts/tieba-archive.mjs list 暗枪
node scripts/tieba-archive.mjs show 11132255511
node scripts/tieba-archive.mjs scans
node scripts/tieba-archive.mjs sync-cache 11132255511 .cache/tieba-11132255511-20261025.json
node scripts/tieba-archive.mjs check
```

查询默认每页10条，最多50条，`--offset`续页。`references`指向人物素材、共享来源或尚未对应角色的事件线索；具体叙事仍维护在这些材料中。本目录不复制原帖全文、图片、联系方式或现实身份，原始抓取留在忽略的缓存。

## 字段与状态

- `thread_id`、`url`：字符串帖号与原帖网址，文件名与帖号一致。`title`、`published_date`只在取得时补齐，不猜日期。
- `acquisition`：最近一次缓存的取得时间、正倒序页次、可见楼层、主楼及楼中楼数量、计数缺口和错误。`sync-cache`只更新这一项，旧缓存不能覆盖更新的快照，不能提升人工状态。
- `review`：唯一当前人工结论。`notes`须写实际读过的范围、未读图片／回复、采用与排除理由及下一步；`evidence`指向归档材料。`read_at`是核读日期，不冒充原帖发表日期。
- `legacy_records`：迁移时逐行保留的旧表原值与来源，包括重复发现的不同来源位置、旧错误、图片缺口和原人工判断。旧判断有矛盾时并存供复核，不自动挑最乐观的一条覆盖。
- `discovery`：本轮发现入口，不等于原帖全文已读。

| 状态 | 含义 |
| --- | --- |
| `unread` | 尚未读原帖全文；可能只筛过列表摘要或取得缓存 |
| `legacy` | 有旧人工结论，具体范围见迁移记录；尚未人工统一成当前结论 |
| `partial` | 已读部分内容，仍有明确的文字或分页缺口 |
| `text-read` | 当时取得的可见文字已读；删楼、计数差、未读图片仍须看说明 |
| `reviewed` | 本次所需文字、图片和处理均已核完，范围仍以说明为准 |
| `excluded` | 有明确排除理由，保留来源防止重复调查 |

`text-read`不等于所有回复和图片完整，`reviewed`不等于以后新增回复已覆盖。取得响应、分页结束、入文、构建成功均不能替代人工核读。

## 迁移与续查

2026-10-25合并原库覆盖、高回复覆盖、中回复、互链发现、互链覆盖五份TSV，以及高回复人工处理表、三份临时冻结JSON清单。旧表的每一行按原值存入对应帖子；迁移来源、行数和SHA-256保存于`scans.json`。旧状态表移除，现有引用改指本目录。

旧调查说明与回复人物线索保留独有的事件、归属边界和身份桥接，作为证据使用；其中历史数字不是当前处理进度。继续调查先查本目录，再读其引用的材料，不再新建日期命名的待查Markdown／TSV。临时`inventory.json`只可作为冻结抓取作业的输入，不再承载正式人工状态；人工处理后更新本目录，未读不能因请求成功而改成已读。

新一轮吧内列表的排序、可见页次、去重帖号、失败和下一步统一记进`scans.json`；新增帖子落入对应JSON。列表筛选、主楼、楼中楼、图片、归档与入文分别说明，原帖新增回复后保留旧范围，再核增量。
