# 列传规则

本页管列传的收录门槛、身份归并、红黑料归类、文风与文件格式；写或改 `src/people/` 下的人物、判断某人能否立传时读。战役见[战役规则](rules-battle.md)，军团见[军团规则](rules-corp.md)，三类规则互不适用。代码路径相对仓库根目录。

本页只定标准。字段示例看[人物模板](person-template.md)，写作展开、判例与验收看[列传验收](person-review.md)，术语看[术语用法](terminology.md)，素材留存看[列传素材归档](materials-person.md)，查人方法看[人物取材](research-person.md)。

## 总方针：够格就收，收了就发挥

这是列传最重要的规则；本页其他规则与它冲突时以它为准。

### 立传门槛

能对上角色，且满足下列任一项 → 立传：

- 有任职依据的军团 CEO。
- 联盟重要管理者：盟主、联盟执行／核心管理、联盟总监、联盟外交或战争负责人等联盟层级的实际工作，不限头衔；本人任一号在联盟执行军团即算。
- 有[指挥依据](#战斗与指挥)的 FC。
- 至少一件较重的红料或黑料：冲突、名场面、圈内议论、重大管理或指挥事件之类。
- 社区公共角色（本身即算较重红料）：B站等平台持续发 EVE 作品的 UP 主与主播，长期写攻略或战报的作者，知名工具／网站作者，汉化与翻译作者，较有名的吧主与社区平台管理者。

硬规则：

- **重大黑料的主角，哪怕只有这一件事，也必须立传**，不放进线索等人决定。大事件主角即使只有一个来源也直接写。
- 够格后料少就写短篇，以后再补；管理者、指挥者与公共角色故事少也留短篇，不因故事少撤回。
- 以下单独或拼凑都**不够**门槛：月榜、累计 KB、参战名单、战果签名（含泰坦／超旗）、KB 分析、简介自嘲、普通聊天、职务头衔本身、几条一般的料。普通成员只有日常吵嘴、普通翻车、零散挖苦、几条轻料的，不立传。
- 军团内部的总监、人事、招新、物流、外交等岗位按普通成员算。
- 帖子、回忆、截图和评论区只是来源形式；有一条发言不等于够门槛。

不够格时：

1. 先读简介全文和 stats 总览，再追具体事件。船型细目、月份与 KM 按[游戏画像](research-person.md#游戏画像)中的实际问题选查，不是统一必查清单。
2. 补不到较重的料 → 留 `docs/leads/` 继续取材。行数不作去留标准；判例见[列传验收](person-review.md#成稿验收)。

### 身份与角色对应

- **不必等本人确认**：本人自报、帖中署名、截图里的角色名、同名且军团或时间吻合，任一即可对应，依据记进素材。
- **小号直接合并**：名字极相近（同词根加数字或字母、大小写或形近字替换、同头衔）且同军团或同联盟 → 判为本人小号，不写“未证实同人”。军团头衔写着已收录人物的名字或外号，再有同军团、同日进出、建号时间或简介任一吻合 → 登记为小号；核实不是的在[军团档案](corporations/README.md)注明。
- **收录号 = 主号**：本人名下 zKB 参与击杀最多的号。入手的老号只算入手后的击杀；被封禁的号无论击杀多少都不作主号。两号击杀相差不到较多者三成时，选更有故事的号。
- **其余号**：ID、正式名字与依据写进本人 `<ID>-id.json` 的 `identity.alts`；别称写 `person.aliases`（战役战报据此认人）。完全找不到角色 → 记入 [docs/pending-characters.md](pending-characters.md)。
- **跨平台账号**：已对应本人的贴吧等账号用第一人称讲自己的事，并贴出同一事件的 B 站视频、动态或主页，且 UP 名与其外号同名、拆字、谐音或惯用变体相合 → 直接归为本人账号，写进[身份档案](person-identity.md)，外号可写 `aliases`；素材记清“本人叙事 → 本人贴链接 → 平台作者名”的链条，不等口播自报或第二来源。只有近似昵称或单纯转发他人作品的，继续按内容与上下文核对。

### 服务器归属

- eve 吧多为国服内容，只作低优先级线索，不作默认补查入口。
- **EVE 手游吧不追查**：搜索、互链或旧队列命中后标【手游吧排除】，只留简短排除记录，不追正文、作者或回复网络，不作宁静服取材依据。
- 同名人物、跨服同名组织和中文角色名都不证明欧服归属。明确国服且无独立欧服交集 → 撤出待收录队列，留排除记录；服务器不明 → 标待核，不套给欧服角色；已对应欧服人物的国服旧事 → 另记同人依据，正文点明发生在国服。方法见[取材手册](research-method.md)贴吧节。

### 出处与发挥

- **唯一的硬约束：事件的存在要有出处。** 谁做了哪件事、核心结果、带链接的数字、当作本人原话引用的话，必须有出处。经过、手法、场面、台词、心理、动机等细节没有材料就放手编满；边界见[列传验收·发挥边界](person-review.md#发挥边界)。
- **料不足就显著发挥**：“不足”指细节不足，不是分量不足。料够重而只剩骨架时，顺着人物处境、利益冲突和言行反差推测动机、串起前因后果，允许夸张、反讽。来源哪怕只有一句话，也展开成一般四五句以上的完整小故事；不能只摘事实再贴一句笑话，也不能把“事件要有出处”扩大成“细节只能复述原帖”。
- **轻料直接放弃**：日常一张 KM、一晚普通行动、普通换团参战、无关痛痒的闲聊，不靠发挥吹大。
- **指控没被证伪就照写**：社区爆料、单方说法、对手宣传都当故事直接讲，出处放链接和素材；不查证、不等当事人认账，正文不写免责声明和考据过程。已被证伪的不写，或写成“谣言被戳穿”。

### 素材与分量

- 有出处的料完整归档（见[列传素材归档](materials-person.md)），重要事件充分入文；此人以什么出名，那件事就是最重的一块。模板里的一红两黑只是格式示例。
- 黑料超过 20 块时按[列传验收](person-review.md#黑料过多时合并与取舍)复核：同一事件合并，低严重度轻料可只留素材；不为凑数拆块，也不为压数删重事。
- 战斗记录按[战绩红料](#战斗与指挥)归纳。未入选精选的 B站作品，其事迹、言论与红黑料照常归档和入文。

### B站 UP 作品精选

人物是 B站 UP 时，从本人频道挑最多 5 个优秀作品放进列传，附标题、公开链接和基于实际读到内容的简短推荐理由。

- **候选**：读本人空间，分别查“最新发布”和“最多播放”，再看合集／系列，不能只看最新首页。优先鲜明个人特色、精彩叙事、实用讲解或出色制作，不只按播放量或标题挑。
- **范围**：翻译、搬运可入选，写明本人承担的翻译、转载或整理，按公开署名分清原作者与上传者，不冒称原创。联合制作不算本人推荐，不占名额。正文红料或黑料已展开的视频不重复推荐。
- **数量**：前两个候选质量较高就继续扩大候选，争取选足 5 个。因去掉正文重复而少选或不放可以；其他情形只有继续筛选后确实不足才少选。未读不等于质量不够，平庸视频不硬塞，没有精选时不显示空块。
- 已确认的 UP 身份不因作品未读完或精选未完成而撤掉。

## 红料与黑料

### 归类

- **黑料** = 此人自己的言行带来的难堪：吵架、滥权、食言、坑人、awox、指挥翻车、自相矛盾、自吹、错字。
- **军团料算 CEO 的**：某人任 CEO（或同级主事者）期间，军团集体干出的黑料（滥刷、不讲规矩、名声烂、被联盟收拾）算他的黑料，不要求证明本人下场；写明“某某军团治下”“其任内”，只算任期内，成员个人私事不算。
- **不算黑料**：普通胜负、普通丢船、KB 低、换团换盟、去对面阵营、联盟解散，军团层面也一样。可作背景，有故事才写；“几年换几家军团”直接不写。
- **被盗号的人是受害者**，不当黑料。指控别人盗号、诈骗等现实违法行为，必须有翔实证据。
- **高价值旗舰战果**：泰坦、超旗的击杀算红料、损失算黑料，只写战果，不推断责任。这只是归类，不能单独撑起立传；不够门槛时先留战果素材。
- **0 伤害不作素材**：KM 显示 0 伤害不代表没出力（显示 bug、后勤、拉点都常见），不拿它评价人或当笑点。
- **不替当事人体面化**：社区黑话照写，强暴就写强暴。
- **立场中立**：写整个华人社区，不站 FRT 或任何一方。打赢 FRT 是战绩，不是黑料。

### 战斗与指挥

- **指挥依据**：本人自称 FC 或记述自己带队、他人称其 FC 或佐证其指挥、公开指挥职务、动员／复盘、驾驶 Monitor 参战，任一即可，不要求必须有 Monitor 记录。zKB 自动 FC 标签只是调查线索。只有概括身份时不补造具体战役与战果，可顺着身份推演带队日常与风格。
- **监视者 = 在指挥位**：开 Monitor（监视者）进战场就是在指挥，开过数十次以上的是重要 FC。正文直接当 FC 写其带过的仗、局势与处境，不提船型、不念次数；KM 数只用来判断指挥分量，不换算成带出的击杀。华人阵营里未对上收录人物的驾驶员按[人物取材](research-person.md#监视者驾驶员反查)反查备案；写法见[列传验收](person-review.md#开监视者的就写他在指挥)。
- **战绩红料写总结性点评**：有显著战斗经历的人，综合战绩单独写成一块红料，紧接开篇之后，不散在开篇、简介段或其他料块里。这块综合 zKB／KB 与战役经历，写战斗风格、长期角色、经历变化和在阵营里的分量。
  - 不列全战役（参战清单已有互链），不逐场报星系、舰船、击杀和损失，不逐张列 KB、念累计数；只展开体现特点、转折、冲突或反差的代表战斗。数字和 KM 链接只在支撑情节或判断时保留，其余归素材与战役页。
  - 精简不能拿几场大仗名单代替综合评价，也不能删掉独立事件、重要指挥经历与红黑料。写法见[列传验收](person-review.md#zkb与战役写点评不写账本)。
- **小号参战**：以自然人为主语，主号小号按事件合并叙述，不分号写履历；角色 ID 和逐号统计留素材，故事需要时才提号名，各号统计不相加。本人小号参战也是本人经历。查 KB 优先参与击杀价值达 100B 的主力号，低于此值可略过，已有参战证据照收。
- KB 累计按其统计范围表述，不把集体战果独算个人功劳。

## 文风

### 口吻

- 戏谑、损而不恶，像熟人互相揭短：读者笑出声，当事人只能苦笑。白话为主，可点缀史书笔法（“时人谓之……”）和社区黑话。
- **说书人口气**：这是野史，推测和想象也用肯定语气，不逐句自我否定。不加“据传”“据某某爆料”“帖主称”“圈内说”“想来”“大概”“看样子”一类护身词，出处放链接和素材。写法见[列传验收](person-review.md#从素材到正文)。
- 中文要地道，不要翻译腔。

### 结构

- 先讲故事：开篇一两段交代此人是谁、在哪混、和谁发生了什么。游戏数据只在服务主线时出现，不堆档案。
- 笑点长在事实后面：先摆事，再一两句损。数字只说它统计的事（KM 上有名字只说明参与了）。
- `epithet` 一句话，≤25 字，要狠；`::: 评` 一两段。

### 不确定时

- **核查账留素材**：待核名单、人数缺口、来源完整度与归因限制写进 `materials-*.json`。正文不用“尚无法确认”“不能证明”“帖里没交代齐”“具体责任不明”之类收尾。来源互相反驳就直接写双方怎么说；影响理解的分歧融进叙事，不列研究问题。
- **换写法，不踩刹车**：人数只有估计就写“百来号人”；不知道谁下令就围绕已点名的人和冲突写，不补造发令者。KB 用“参与”，自吹用“他自称”，不先夸大再补一句“这不能证明”。

### 语言与来源

- 术语用 `npm run glossary -- "词语"` 定向查询，遵守[术语用法](terminology.md)。
- **外文原话译成中文**：照原话的损劲儿译，不留整句外文。读者可能拿去搜的帖子标题、口号、绰号，译文后括注原文；人名、组织名、舰船名、术语按术语用法。原文留素材。
- 截图、私聊、群聊来的料直接写事，不描述截图、群名、时间。有网址的公开帖附链接。

### 禁区

现实隐私（真名、单位、住址、电话、照片）；地域、民族、性别、外貌歧视；未成年人不收；游戏世界观与 NPC 势力（种族、NPC 学校、NPC 军团）不写，进出 NPC 军团只说“换军团”“退团”。

### 文风验收

写作前读[列传验收与改写例](person-review.md)，成稿按其标准通读。罗列素材缺口、为来源辩护、消毒式结尾都算未完成；只删免责句也不够，要把线索展开成人物故事与锐评。重料另按[分量与发挥验收](person-review.md#重料的分量与发挥验收)逐件审，战斗调查结论不能代替写作结论。

## 文件格式

### 目录

每人一个目录 `src/people/<短名>/`（小写字母、数字、连字符）：

- `<短名>.md`：列传；`materials-<短名>.json`：素材与来源（不生成页面）。
- `<ID>-id.json`：展示配置、游戏快照与人工身份共用的档案；游戏字段由抓取维护，展示配置写 `person`，人工关系写 `identity`，详见[人物身份数据](person-identity.md)。`portrait-<ID>.jpg` 为头像。
- 以 `_` 开头的文件被忽略。模板见 [docs/person-template.md](person-template.md)。

### 人物 JSON 配置

Markdown 只保留正文，不写 front matter。收录角色 ID 只在 `<ID>-id.json` 顶层 `id` 维护，并与文件名一致；中文名、别称、锐评和标签集中在 `person`。示例见[人物模板](person-template.md)，字段、小号与刷新规则见[人物身份数据](person-identity.md)。

- `aliases` 只放外号、简称和社区别称；小号是独立游戏角色，按 `identity.alts` 维护，不重复塞进别称。
- 角色名、创号时间、军团等游戏数据由脚本提供，不手写。
- `tags` 的取舍、身份标签与主要联盟 ticker 规则见[列传验收](person-review.md#标签)；`npm run check`、`npm run build` 会校验组织标签。

### 名人与特殊标记

各标记彼此独立，可同时并存。人物面板可附六维雷达品评，标准见[列传六维品评](person-radar.md)；评分不自动授予或撤销下列标记，但首次设分与重核必须先按雷达规范核对既有战神／大亨标记及对应最低档。

| 标记 | 判定 | 维护位置 | 展示 |
| --- | --- | --- | --- |
| 名人 | 人工，同时满足“跨圈”与“时间沉淀”（见下） | `src/_data/famousPeople.js`，名单加一句公开理由，照列传事实写，不写进人物档案 | — |
| 战神 | 自动：收录号与全部已登记小号累计参与击杀总价值满 10 万亿 ISK；或按主号创号至最晚击杀（至少按 2 年折算）年均参与击杀价值满 1.5 万亿 ISK | `scripts/activity.mjs` | 姓名旁朱砂双刃准星击杀勋章 |
| 大亨 | 人工：列传有明确事迹证明显著商业或工业活动（见下） | `src/_data/tycoonPeople.js`，名单加一句事迹 | 鎏金边框与底部重工齿轮 × 飞翼金砖星币托座 |
| 神人 | 人工：黑料极为夸张、出格、有碍公序良俗或脑回路异于常人（见下） | `src/_data/shenrenPeople.js`，名单加一句事迹 | 微歪头像、头顶断裂电弧神环与跳动的“？！”脑电波 |
| UP 主 | 自动：已确认本人的 B 站账号下，按 BV 去重后播放量满 3000 的 EVE 视频不少于 10 条（非 EVE 综合号除外） | 构建判定 | 头像左下角 B 站粉红双天线小电视挂件 |

- **名人**：**跨圈**指自家联盟、军团之外也有人知道，或靠视频、翻译、教程、比赛被圈外认识；全服论坛、赛船圈、外服来源里的名气同样算。**时间沉淀**指名字多年后还被提起；一两年闹出跨圈大事就沉寂的不算。料多不等于有名，料少也不等于没名；站内链接数、贴吧帖数只作线索。老资格只作辅助，单凭资历不算。视频作者看 EVE 视频总播放：超过 10 万且做满两年即算名人；非 EVE 视频不计，零星旧片不算年头，不够线要另有名气。
- **大亨**事迹举例：大型旗舰／装备制造、跨星域物流快递、月矿管理与大规模采矿生产、大宗赛船／蓝图／牌子／超网交易、军团银行与债券运营。
- **神人**举例：动辄扬言买命开盒、华人团禁说中文又选中文代表、把捐助写成色情谍战、强搞奇葩个人崇拜／闹剧。普通对喷、常规战术翻车或一般内讧不算。

### 正文

```markdown
开篇叙事。

::: 红料 标题
……
:::

::: 黑料 标题
……
:::

::: 评
文末锐评。
:::
```

- 每个独立事件一块，同一事件的后续合并叙述；块不能嵌套，以单独一行 `:::` 结束。一般先红后黑。
- 单个换行即换行；聊天记录用 `> 某某 > 这船怎么又炸了`，每行一句。
- 不用 `#` 一级标题。
- 提到已有列传的人加互链，写相对路径 `[名字](../<角色ID>/)`，不要以 `/` 开头。
- 引用已有战役页时链到 `../../battles/<短名>/`，链接文字的星系名写中文，KM 链接照留。
- 术语蓝字由构建自动生成，见[术语用法](terminology.md)。
