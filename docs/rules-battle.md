# 战役规则

只管战役页。列传见[列传规则](rules-person.md)，军团见[军团规则](rules-corp.md)，三类规则互不适用；这里没写的，不去那边找。字段、正文结构与互链写法见[战役模板](battle-template.md)，成稿按[战役验收](battle-review.md)，流程用 `add-battle`，专名写法看[术语用法](terminology.md)。

## 收录与统计

- **先判是不是战役**：少数旗舰出事、人数悬殊的单方面围猎或转移事故不收为战役，不能靠昂贵舰船把总损失推过 100B 就立页，这类事件留在相关列传与素材（例：2023-10-17 HED-GP 代驾事故）。
- **规模分档**：按各方总损失（单位 B）自动分档，100B–不足 400B 为**中型**，400B–不足 1T 为**大型**，1T 及以上为**史诗**；不足 100B 构建失败。总损失必须附来源 `loss_source`。
- 一场一篇：`src/battles/<短名>/<短名>.md`，素材 `materials-<短名>.md`。同一星系先后几场按单场时间窗口分开写；几天内接连打的同一轮攻防，单场不足门槛或分量偏轻的编为一场（如 Y-MPWL 2025-08-19—08-25）：`start`／`end` 覆盖全程，总损失为各场之和，`loss_source` 列各场战报。已编进一组的单场不另立页；同一星系日期重叠的两页构建失败。
- **星系名用中文**：标题和正文按[术语用法](terminology.md)写中文；`systems`、路径、英文别名和来源原题保留英文。
- **战役标签**分为规模、战斗类型、地带、参战联盟四组，创建标准与字段见[下文战役标签](#战役标签)。规模由损失自动分档；战斗类型只取超旗战、旗舰战、常规战，每场恰选一类，按下文投入门槛判断，不能以损失金额或旗舰是否被击毁代替投入判断。联盟有成员参与本场就须有标签，包括配角、增援、第三方，不设人数门槛，不按主角或现今外交筛选；参战标签不代表联盟整体动员或统一指挥。联盟标签由本场历史记录自动生成，使用游戏内 ticker；不再手填联盟、船型、建筑目标、战争名称或“混战”等杂项标签。
- **联盟、军团写 ID**：同名战役 JSON 里 `battle.sides[].organizations` 的联盟／军团和手填军团只写 ID，名字由全站名称表 `src/_data/entityNames.json` 提供；ID 用 `npm run find -- "全名"` 查，表里没有的由 `npm run fetch` 向 ESI 补。**华人军团**在名称表里加 `"chinese": true`，全站快照战役据此自动列出、计人数；非华人军团（如 GoonWaffe）里有华人成员也不标。
- **先核完整分队，再写阵营**：实际打开 BR 网页，展开全部组织列表，记录组织 ID 及逐方人数、金额、损失条数，再与当事人复盘、逐舰记录和已确认的本场关系交叉核对。BR 会分错，默认分组不能盲从；原作者完整 BR 通常比自动 related 更能解释编组，但同样要核；API 缺 `teams` 不等于网页没分队，不能据此自行拆分联盟。来源冲突时逐项记差异与采用理由，已有明确依据的归属不因默认 BR 不同而被覆盖；未查清的留待核，不编换边或内讧。零散交叉命中、智能炸弹伤害、对多家组织开火、未归组余额和长期外交关系，都不能单独证明第三方。改分方须同步数字、人物与军团归属、正文和素材。
- **快照战役（首选）**：`loss_source` 全是 br.evetools 或 killmail.app 完整战报时，`npm run fetch`／`build` 把战报精简存进同名 JSON 的 `br`（勿手改）。人数、损失、记录条数、华人军团和参战的已收录人物都由快照算，不手填数字、`people` 或华人军团；`organizations` 是唯一的组织归方名单，`emblem` 只选主标，战报跨场时用 `window` 截时段。自动归方和联盟收纳只是后备，不替代上一条的人工核对；算法与展示门槛见[战役模板](battle-template.md#快照归方与统计)。
- **同一联盟不跨方**：同一场里同一联盟及其军团必须同方，跨方即归方错误：回查本场历史归属，修正组织映射、正文和素材，不解释为军团独立站队。归属取本场快照，不用军团当前联盟回填。联盟出现只说明有成员在场，不代表整体动员或统一指挥。附属联盟（后勤、学院联盟）一律随主联盟同方，名单维护在 `scripts/battles.mjs` 的 `SISTER_ALLIANCES`，构建校验拦截跨方。
- **手填战役**：来源是 CCP 新闻、WarBeacon、EVE-KILL、论坛自报等其他口径时，总损失和各方人数、损失、记录条数照来源手填，全场数不能顶替分方数；取不到才写 `null` 并填 `stats_note`，0 只表示来源确认没有损失。字段见战役模板；窗口、星系、阵营映射与差异留素材。
- 正文按阵营分节，写各方的华人人物与华人军团。
- **相关视频**：页首推荐最多 8 个与本场直接相关的视频，B站为主，史诗档可含 1 个 YouTube。尽量兼顾各方视角，但不强求均衡，不为凑数或等量增删；没有合适作品就不显示。转载、合作按公开署名写明原作者，介绍只写已读到的内容，不编阵营或驾驶者。关联判断按[战役取材](research-battle.md#来源对战役时区与战报)，字段格式见战役模板。

## 战役标签

目录筛选与详情页使用同一组标签，分四类，联盟标签只按参战占比取舍，不因正文只写某些主角而增减：

| 分类 | 创建标准 | 维护方式 |
| --- | --- | --- |
| 规模 | 中型、大型、史诗，按全场损失分档 | 自动生成，不手填 |
| 战斗类型 | 超旗战、旗舰战、常规战，每场恰选一个 | 写进 `battle.tags`，依据留本场素材 |
| 地带 | 00区、低安、高安、虫洞、三神裔，每场恰选一个 | 写进 `battle.tags`，按实际战场选取 |
| 参战联盟 | 参战角色数达到所在一方参战角色总数的30%及以上；配角、增援与零星参战不上标签 | 从本场历史参战记录生成游戏内 ticker，去重；不手填 |

**战斗类型判断**：交战双方须在同一战斗阶段同时各投入至少10条超旗，才归超旗战；超旗只计泰坦与超级航母，两类合计。须核双方投入数量与同时交战的依据，不能用单条攻击记录、单方超旗投入、全场累计出勤或超旗损失数代替。只有投送开桥、待命或被困撤离本身不计实际交战。未达到或无法证实这一门槛时，按其余已核投入判断：大量无畏、普通航母成建制投入并交锋构成重要战斗阶段，归旗舰战；常规舰队为主，仅少量旗舰支援或完全没有旗舰，归常规战。普通航母与战力辅助舰不算超旗；旗舰战和常规战须结合投入规模、战斗经过判断，不以最贵KM、总损失或“有一条无畏”机械升级。没有超旗损失也可能达到超旗战门槛；损失快照不含舰型与同时在场数量，不能只靠快照金额自动猜分类。编组按所含实际交战且达到门槛的最高层级归类，不把未发生的升级预告算进去。

**联盟范围**：快照战役从所有阵营的 `alliance_participation` 取并集，只留本方角色占比达30%的联盟（含不足30人而隐藏的第三方里达标者），人数不足10人但占比达标的联盟同样保留，仅留有损失记录的联盟不上标签。手填战役从已核 `organizations` 中的联盟及 `corps[].alliance_id` 取并集；缺漏须据本场来源补历史组织，不能用军团当前所属联盟回填。独立军团不冒充联盟标签。联盟尚缺名称／缩写时补取官方资料，确实查不到则保留稳定的“联盟 #ID”标签，不猜缩写、不静默漏掉；名称与ticker缺项须报告。显示小方及阵营名单的原门槛与标签范围分别处理。

**清理标准**：不另建“泰坦战／无畏战／战列战／常规舰战”等同义类别；“星城、星城战、拆堡、建筑攻防、主权战、北方战争、混战”等目标、背景或含糊词退出标签，事实仍保留在标题、别名、正文与素材。不得为单场临时造新标签；新增维度先修订本节分类和共享校验，再回查受影响条目。

## 人物归因

- **以自然人为主语**：主号小号按事件合并叙述，不分号写履历；角色 ID 和逐号统计留素材，故事需要时才提号名，各号统计不相加。本人小号参战也是本人经历。
- **监视者 = 在指挥位**：开 Monitor（监视者）进战场就是在指挥。正文直接当 FC 写其带的仗、局势与处境，不提船型、不念次数；KM 数只用来判断指挥分量，不换算成带出的击杀。华人阵营里未对上收录人物的驾驶员按[人物取材](research-person.md#监视者驾驶员反查)反查备案。
- **指挥依据**：本人自称 FC 或记述自己带队、他人称其 FC 或佐证其指挥、公开指挥职务、动员／复盘、驾驶 Monitor 参战，任一即可，不要求必须有 Monitor 记录。只有概括身份时不补造本场的具体战果。zKB 自动 FC 标签只是调查线索。
- KB 累计按其统计范围表述，不把集体战果独算个人功劳。
- **立场中立**：写整个华人社区，不站 FRT 或任何一方。打赢 FRT 是战绩，不是黑料。
- **被盗号的人是受害者**，不当黑料；指控别人盗号、诈骗等现实违法行为，需要有翔实证据。

## 红料与黑料

- **黑料** = 当事人自己的言行带来的难堪：吵架、滥权、食言、坑人、awox、指挥翻车、自相矛盾、自吹、错字。
- **不算黑料**：普通胜负、普通丢船、KB 低、换团换盟、去对面阵营、联盟解散，军团层面也一样。可作背景，有故事才写。
- **0 伤害不作素材**：KM 显示 0 伤害不代表没出力，不拿它评价人或当笑点。
- **高价值旗舰战果**：泰坦、超旗的击杀算红料、损失算黑料，只写战果，不推断责任。
- **指控没被证伪就照写**：社区爆料、单方说法、对手宣传都当故事直接讲，出处放链接和素材；不查证、不等当事人认账，正文不写免责声明和考据过程。已被证伪的不写，或写成“谣言被戳穿”。
- **不替当事人体面化**：社区黑话照写，强暴就写强暴。

## 文风

- 戏谑、损而不恶，像熟人互相揭短：读者笑出声，当事人只能苦笑。白话为主，可点缀史书笔法（“时人谓之……”）和社区黑话。
- 先讲故事：开篇交代这场仗为什么打、谁和谁、局面怎么翻的。统计由页面自动生成，正文取指挥、动员、名场面、重大损失、阵前跳槽，不用统计清单代替故事。
- 笑点长在事实后面：先摆事，再一两句损。数字只说它统计的事（KM 上有名字只说明参与了）。
- **事件要有出处，细节放手编**：谁做了哪件事、核心结果、带链接的数字和当作本人原话引用的话要有出处；经过、手法、场面、心理、动机等细节没有材料就编满。料够重而细节不足时，来源哪怕只有一句话，也展开成一般四五句以上的完整小故事，不能只摘事实再贴一句笑话。客观上轻的料直接放弃，不靠发挥吹大。
- **口吻不保守**：用说书人的口气直接讲，推测和想象也用肯定语气。不加“据传”“据某某爆料”“帖主称”“圈内说”“想来”“大概”“看样子”一类护身词，出处放链接和素材。
- **正文讲人和事，核查账留素材**：待核名单、人数缺口、来源完整度与归因限制写进 `materials-*.md`，正文不用“尚无法确认”“不能证明”之类收尾。来源互相反驳就直接写双方怎么说。
- **不确定细节就换写法**：人数只有估计就写“百来号人”；不知道谁下令就围绕已点名的人和冲突写，不补造发令者。KB 用“参与”，自吹用“他自称”。
- 中文要地道，不要翻译腔。术语与游戏内专名按[术语用法](terminology.md)。
- **外文原话译成中文**：外文发言、帖子、评论在正文写中文译文，照原话的损劲儿译，不留整句外文。读者可能拿去搜的帖子标题、口号、绰号，译文后括注原文。原文留素材。
- 截图、私聊、群聊来的料直接写事，不描述截图、群名、时间。有网址的公开帖附链接。
- **改写只能变长**：修订已有战役，故事不能写短。
- **禁区**：现实隐私（真名、单位、住址、电话、照片）；地域、民族、性别、外貌歧视；未成年人不收；游戏世界观与 NPC 势力（种族、NPC 学校、NPC 军团）不写，进出 NPC 军团只说“换军团”“退团”。

## 素材

- 一场一份 `materials-<短名>.md`，放本场事实与出处：战报来源与窗口、完整组织映射、来源冲突与采用理由、逐方核对结果、当事人复盘。多场共用的事件摘要放 `docs/sources/`。
- 先留存，再决定是否入文：关键原文、必要上下文、出处、时间、作者和角色对应都留；暂时用不上或看不出用途的也留，写明待核。现实隐私不留。
- 外部图片、聊天记录、PDF 读懂后写成摘要，不全文转录，不存文件名、哈希和二进制。不记录素材提供者身份或对话过程。
