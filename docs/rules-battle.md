# 战役规则

本页管战役页的立页门槛、分方与统计、标签、人物归因、叙事写法和素材；写或改 `src/battles/` 下的任何文件时读，含只登记小号、补一行素材。列传见[列传规则](rules-person.md)，军团见[军团规则](rules-corp.md)，三类规则互不适用；这里没写的，不去那边找。

字段、正文结构与互链写法见[战役模板](battle-template.md)，成稿按[战役验收](battle-review.md)，流程用 `add-battle`，专名写法看[术语用法](terminology.md)。

## 收录与统计

### 立页门槛

- **先判是不是战役**：少数旗舰出事、人数悬殊的单方面围猎或转移事故不收为战役，不能靠昂贵舰船把总损失推过 100B 就立页；这类事件留在相关列传与素材（例：2023-10-17 HED-GP 代驾事故）。
- **规模分档**（按各方总损失，单位 B，自动分档）：100B 至不足 400B → **中型**；400B 至不足 1T → **大型**；1T 及以上 → **史诗**；不足 100B → 构建失败。总损失必须附来源 `loss_source`。

### 一场一篇

- 路径 `src/battles/<短名>/<短名>.md`，素材 `materials-<短名>.json`。
- 同一星系先后几场 → 按单场时间窗口分开写。
- 几天内接连打的同一轮攻防，单场不足门槛或分量偏轻 → 编为一场（如 Y-MPWL 2025-08-19—08-25）：`start`／`end` 覆盖全程，总损失为各场之和，`loss_source` 列各场战报。已编进一组的单场不另立页；同一星系日期重叠的两页构建失败。
- 标题和正文的星系名按[术语用法](terminology.md)写中文；`systems`、路径、英文别名和来源原题保留英文。

### 组织与阵营

- **联盟、军团写 ID**：`battle.sides[].organizations` 的联盟／军团和手填军团只写 ID，名字由全站名称表 `src/_data/entityNames.json` 提供。ID 用 `npm run find -- "全名"` 查，表里没有的由 `npm run fetch` 向 ESI 补。
- **华人军团**在名称表里加 `"chinese": true`，全站快照战役据此自动列出、计人数；非华人军团（如 GoonWaffe）里有华人成员也不标。
- **先核完整分队，再写阵营**：
  1. 实际打开 BR 网页，展开全部组织列表，记录组织 ID 及逐方人数、金额、损失条数。
  2. 与当事人复盘、逐舰记录和已确认的本场关系交叉核对。BR 会分错，默认分组不能盲从；原作者完整 BR 通常比自动 related 更能解释编组，但同样要核。API 缺 `teams` 不等于网页没分队，不能据此自行拆分联盟。
  3. 来源冲突时逐项记差异与采用理由；已有明确依据的归属不因默认 BR 不同而被覆盖；未查清的留待核，不编换边或内讧。
  4. 改分方须同步数字、人物与军团归属、正文和素材。
- **不能单独证明第三方**：零散交叉命中、智能炸弹伤害、对多家组织开火、未归组余额、长期外交关系。
- **同一联盟不跨方**：同一场里同一联盟及其军团必须同方，跨方即归方错误 → 回查本场历史归属，修正组织映射、正文和素材，不解释为军团独立站队。归属取本场快照，不用军团当前联盟回填。附属联盟（后勤、学院联盟）一律随主联盟同方，名单维护在 `scripts/battles.mjs` 的 `SISTER_ALLIANCES`，构建校验拦截跨方。
- 联盟出现只说明有成员在场，不代表整体动员或统一指挥。

### 统计来源

- **快照战役（首选）**：`loss_source` 全是 br.evetools 或 killmail.app 完整战报时，`npm run fetch`／`build` 把战报精简存进同名 JSON 的 `br`（勿手改）。人数、损失、记录条数、华人军团和参战的已收录人物都由快照算，不手填数字、`people` 或华人军团。`organizations` 是唯一的组织归方名单，`emblem` 只选主标，战报跨场时用 `window` 截时段。自动归方和联盟收纳只是后备，不替代上文人工核对；算法与展示门槛见[战役模板](battle-template.md#快照归方与统计)。
- **手填战役**：来源是 CCP 新闻、WarBeacon、EVE-KILL、论坛自报等其他口径时，总损失和各方人数、损失、记录条数照来源手填，全场数不能顶替分方数。取不到才写 `null` 并填 `stats_note`；0 只表示来源确认没有损失。字段见战役模板；窗口、星系、阵营映射与差异留素材。

### 相关视频

- 页首推荐最多 8 个与本场直接相关的视频，B站为主，史诗档可含 1 个 YouTube；没有合适作品就不显示。
- 尽量兼顾各方视角，但不强求均衡，不为凑数或等量增删。
- 转载、合作按公开署名写明原作者；介绍只写已读到的内容，不编阵营或驾驶者。
- 关联判断按[战役取材](research-battle.md#来源对战役时区与战报)，字段格式见战役模板。

## 战役标签

目录筛选与详情页使用同一组标签，分四类。不为单场临时造新标签；新增维度先修订本节和共享校验，再回查受影响条目。

| 分类 | 创建标准 | 维护方式 |
| --- | --- | --- |
| 规模 | 中型、大型、史诗，按全场损失分档 | 自动生成，不手填 |
| 战斗类型 | 超旗战、旗舰战、常规战，每场恰选一个 | 写进 `battle.tags`，依据留本场素材 |
| 地带 | 00区、低安、高安、虫洞、三神裔，每场恰选一个 | 写进 `battle.tags`，按实际战场选取 |
| 参战联盟 | 参战角色数达到所在一方参战角色总数的 30% 及以上 | 从本场历史参战记录生成游戏内 ticker，去重；不手填 |

### 战斗类型

按投入判断，不以损失金额、最贵 KM 或旗舰是否被击毁代替：

- **超旗战**：交战双方在同一战斗阶段同时各投入至少 10 条超旗（只计泰坦与超级航母，两类合计）。须核双方投入数量与同时交战的依据；单条攻击记录、单方超旗投入、全场累计出勤或超旗损失数都不能代替。只有投送开桥、待命或被困撤离不计实际交战。没有超旗损失也可能达到此门槛。
- **旗舰战**：未达到或无法证实超旗战门槛，但大量无畏、普通航母成建制投入并交锋，构成重要战斗阶段。普通航母与战力辅助舰不算超旗。
- **常规战**：常规舰队为主，仅少量旗舰支援或完全没有旗舰。不因“有一条无畏”机械升级。
- 损失快照不含舰型与同时在场数量，不能只靠快照金额自动猜分类。
- 编组按所含实际交战且达到门槛的最高层级归类，不把未发生的升级预告算进去。

### 参战联盟

- 只按参战占比取舍，不因正文只写某些主角而增减；配角、增援与零星参战不足 30% 不上标签。参战标签不代表联盟整体动员或统一指挥。
- **快照战役**：从所有阵营的 `alliance_participation` 取并集，只留本方角色占比达 30% 的联盟（含不足 30 人而隐藏的第三方里达标者）；人数不足 10 人但占比达标的同样保留；仅有损失记录的联盟不上标签。
- **手填战役**：从已核 `organizations` 中的联盟及 `corps[].alliance_id` 取并集；缺漏须据本场来源补历史组织，不能用军团当前所属联盟回填。
- 独立军团不冒充联盟标签。联盟缺名称／缩写时补取官方资料；确实查不到则保留稳定的“联盟 #ID”标签，不猜缩写、不静默漏掉，名称与 ticker 缺项须报告。
- 显示小方及阵营名单的门槛与标签范围分别处理。

### 不再使用的标签

- 不另建“泰坦战／无畏战／战列战／常规舰战”等同义类别。
- “星城、星城战、拆堡、建筑攻防、主权战、北方战争、混战”等目标、背景或含糊词，以及联盟、船型、建筑目标、战争名称等手填杂项，不作标签；事实仍保留在标题、别名、正文与素材。

## 人物归因

- **以自然人为主语**：主号小号按事件合并叙述，不分号写履历；角色 ID 和逐号统计留素材，故事需要时才提号名，各号统计不相加。本人小号参战也是本人经历。
- **指挥依据**：本人自称 FC 或记述自己带队、他人称其 FC 或佐证其指挥、公开指挥职务、动员／复盘、驾驶 Monitor 参战，任一即可，不要求必须有 Monitor 记录。只有概括身份时不补造本场的具体战果。zKB 自动 FC 标签只是调查线索。
- **监视者 = 在指挥位**：开 Monitor（监视者）进战场就是在指挥。正文直接当 FC 写其带的仗、局势与处境，不提船型、不念次数；KM 数只用来判断指挥分量，不换算成带出的击杀。华人阵营里未对上收录人物的驾驶员按[人物取材](research-person.md#监视者驾驶员反查)反查备案。
- KB 累计按其统计范围表述，不把集体战果独算个人功劳。
- **立场中立**：写整个华人社区，不站 FRT 或任何一方。打赢 FRT 是战绩，不是丑事。
- **被盗号的人是受害者**，不拿来当笑点；指控别人盗号、诈骗等现实违法行为，必须有翔实证据。

## 叙事与高潮

战役正文是一个按时间线讲的故事，不分红料、黑料。旧稿里的红料、黑料块只为兼容暂留；新写或修订一场战役时，整篇改成本节写法，不新旧混用。

### 时间线

- 按“起因 → 集结 → 交锋 → 转折 → 收场”推进，用自拟的 `##` 小节标题点出每个阶段（如“## 一张开桥令”），不按阵营分节，也不用“甲方／乙方”作标题。阶段可合并或省略，顺序不倒。
- 开篇交代这场仗为什么打、谁和谁。各方的华人人物与华人军团在故事里随事件出场；每个有华人戏份的阵营都要有人出场，不另列名单。
- 统计由页面自动生成，正文不用统计清单代替故事；数字只在推动情节时出现，且只说它统计的事（KM 上有名字只说明参与了）。
- 文末用 `::: 评` 一两段锐评收尾。

### 高潮块

- 用 `::: 高潮 标题` 框出全篇最精彩的场面，一般 2–3 块，最多 4 块；放在时间线上它发生的位置，不集中堆到文末。没有够分量的场面就不硬造。
- **够格**：改变战局的转折、名场面、重大损失、阵前跳槽、指挥神来之笔或翻车、动员或谈判的关键一刻。泰坦、超旗的击杀与损失够格，只写战果，不推断责任。
- **不够格**：一张普通 KM、一次普通出勤、普通胜负与丢船、换团换盟。可作过场，不进高潮块。
- 高潮块不分褒贬：荣光和丑事都可以是高潮，标题点出场面本身（如“三十秒的超旗墙”），不写“红”“黑”。
- 每块是一个完整场面，一般四五句以上：谁在什么局面下做了什么、怎么翻的、各方什么反应，再一两句损。块外的时间线负责衔接，块内不重讲背景。

### 什么可以写

- 当事人自己的言行带来的难堪（吵架、滥权、食言、坑人、awox、指挥翻车、自相矛盾、自吹、错字）照写，放在故事里讲。
- 普通胜负、普通丢船、KB 低、换团换盟、去对面阵营、联盟解散只作背景，有故事才写，不当笑点。
- **0 伤害不作素材**：KM 显示 0 伤害不代表没出力，不拿它评价人或当笑点。
- **指控没被证伪就照写**：社区爆料、单方说法、对手宣传都当故事直接讲，出处放链接和素材；不查证、不等当事人认账，正文不写免责声明和考据过程。已被证伪的不写，或写成“谣言被戳穿”。
- **不替当事人体面化**：社区黑话照写，强暴就写强暴。

### 出处与发挥

- **事件要有出处，细节放手编**：谁做了哪件事、核心结果、带链接的数字、当作本人原话引用的话必须有出处；经过、手法、场面、心理、动机等细节没有材料就编满。
- 场面够重而细节不足时，来源哪怕只有一句话，也展开成完整场面，不能只摘事实再贴一句笑话。客观上轻的事直接放弃，不靠发挥吹大。
- **改写只能变长**：修订已有战役（含从红黑料块改成时间线），故事不能写短，原有已认可的事件不丢。

## 文风

### 口吻

- 戏谑、损而不恶，像熟人互相揭短：读者笑出声，当事人只能苦笑。白话为主，可点缀史书笔法（“时人谓之……”）和社区黑话。
- **说书人口气**：推测和想象也用肯定语气。不加“据传”“据某某爆料”“帖主称”“圈内说”“想来”“大概”“看样子”一类护身词，出处放链接和素材。
- 笑点长在事实后面：先摆事，再一两句损。
- 中文要地道，不要翻译腔。

### 不确定时

- **核查账留素材**：待核名单、人数缺口、来源完整度与归因限制写进 `materials-*.json`，正文不用“尚无法确认”“不能证明”之类收尾。来源互相反驳就直接写双方怎么说。
- **换写法**：人数只有估计就写“百来号人”；不知道谁下令就围绕已点名的人和冲突写，不补造发令者。KB 用“参与”，自吹用“他自称”。

### 语言与来源

- 术语与游戏内专名按[术语用法](terminology.md)。
- **外文原话译成中文**：照原话的损劲儿译，不留整句外文。读者可能拿去搜的帖子标题、口号、绰号，译文后括注原文。原文留素材。
- 截图、私聊、群聊来的料直接写事，不描述截图、群名、时间。有网址的公开帖附链接。

### 禁区

现实隐私（真名、单位、住址、电话、照片）；地域、民族、性别、外貌歧视；未成年人不收；游戏世界观与 NPC 势力（种族、NPC 学校、NPC 军团）不写，进出 NPC 军团只说“换军团”“退团”。

## 素材

- 一场一份 `materials-<短名>.json`，放本场事实与出处：战报来源与窗口、完整组织映射、来源冲突与采用理由、逐方核对结果、当事人复盘。多场共用的事件摘要放 `docs/sources/`。
- 先留存，再决定是否入文：关键原文、必要上下文、出处、时间、作者和角色对应都留；暂时用不上或看不出用途的也留，写明待核。现实隐私不留。
- 外部图片、聊天记录、PDF 读懂后写成摘要，不全文转录，不存文件名、哈希和二进制。不记录素材提供者身份或对话过程。
