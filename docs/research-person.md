# 人物取材

人物够格就可以先立传，料以后再补（门槛见[列传规则](rules-person.md)的“总方针”）。本页只写怎么查人，联网预算和平台读法见[取材手册](research-method.md)。材料写进本人 `materials-<短名>.json` 或 `docs/leads/`。

## 取材方向

- **先问此人以什么出名。** 那件事必须是列传最重的一块。游戏数据用于理解人物经历；只有数据与正文的身份、职责或事件判断相冲突时，才沿具体问题补查。
- **名册先认人，再追故事。** 军团榜先批读头衔、完整简介并合并同人；有管理职责、FC 自述、明确事件或作者入口的再展开。普通成员只有 KB 入口就留素材，不拿补齐战果代替故事。同类批处理复用已有脚本。
- **搜索关键词**（“某某”换成中文名、外号、角色名）：

| 目的 | 关键词 |
| --- | --- |
| 评价 | `某某 eve欧服吧`、`如何评价某某` |
| 黑料 | `某某 封号` `吧主` `洗号` `骗` `RMT` `跑路` `叛逃` `谴责某某` `强暴` `举报` |
| 已对应欧服人物的国服旧账（另核同人） | `某某 eve吧`、`某某 国服` |
| 整理文 | `某某 EVE领航员`、`名人堂`、`传奇` |

## 游戏画像

`node scripts/research/profile.mjs <角色ID> [论坛用户名] > 画像.md`

先复用快照与已有画像，缺失且影响本次判断时补跑；报路径错误先用 `npm run doctor` 修环境。脚本汇总头衔与简介全文、各段军团当时所在联盟、zKillboard 常用船／星系／高价值月份、凛冬论坛本人主题与回帖；这些是可用信息，不是逐项补齐清单。重点看：

- 本人写的角色简介，常常就是最好的料；凛冬论坛标题带敏感词（强暴、骗、举报……）的帖子必读。
- 某月 ISK 暴增可作相关事件的检索线索，不能直接判定战役规模或个人功劳，也不自动触发逐月取 KM。

**量级先看 stats，一页足够就停止。** `zkillboard.com/api/stats/characterID/<ID>/`（网页版 `/character/<ID>/stats/`）的累计、近期及逐月统计足以判断战斗频率和规模，收录号与已确认主力小号均可复用已有统计。只有具体事件、职责或正文判断需要时，才查相应船型、星系或代表 KM，从对应月份或[高级搜索](research-tools.md#zkillboard-高级搜索asearch)取少量记录。可选细目未查全、取数失败或预算用尽，不影响已由总览支持的判断，也不单独阻止列传交付；影响身份、指挥归因或具体战果的证据缺口仍须处理。

**认船不凭记忆。** 解读 `topShips` 或 KM 船型前，用 ESI `universe/names`／`universe/types/<ID>/` 或已核舰船表解析 ID；`appearances` 不等于全生涯使用次数。Monitor 的 typeID 为 **45534**（groupID 1972），**35683 是 Hecate**，不能当指挥依据。自动 `fc` 标记只作线索，实际指挥按列传规则的“指挥依据”核。

需要细查时：zKillboard `api/kills/characterID/<ID>/year/<Y>/month/<M>/`（curl 加 `-L`），只取选定的一两个月；ESI `killmails/<id>/<hash>/`；DOTLAN 军团事件史。查任期和历史归属见[军团榜单与历史 CEO](research-method.md#军团榜单与历史-ceo)。

**战役补漏。** 人物页的战役反链自动生成，素材只补战报看不出的参战／指挥依据，不以月度累计代替战报。大范围补漏先[发现战役再反查人物](research-battle.md#发现战役与读战报)；取得完整战报后，对照全部收录号与已对应主力小号，再查具体舰船、阵营和 Monitor／动员／复盘依据。高价 KM 样本可用来发现人，不能定整场金额，也不能用零命中排除参战。宽窗口多星系 BR 中，人物只在无关星系命中的，不认定参加主战。战役规模与本人参战都有依据才补战绩正文。

**小号也查，号多时最多查两个。** 从本人素材与别名取已对应小号，只查 KB 最好或最近最活跃的一两个（优先参与击杀价值 ≥100B 的主力号），其余不查，已有直接证据的照样入料。高价值样本未命中时，再查主力号在该星系、该月的记录；样本零命中不等于未参战，各号累计不相加。

## 贴吧认人

**角色对不上时，先读已取得的全文与帖尾，不只看截断摘要。** 长帖作者常在后期楼层贴游戏聊天记录（`[ 2025.02.28 13:44:48 ] 某某 > ……`），自己的角色名就在其中，所以先从真正末页读起（客户端倒序的坑见[工具细节](research-tools.md#贴吧客户端)）。再拿帖中回忆的具体击杀（日期、船型、总值、掉落）去 zKillboard 对，用户名变体用 `npm run find` 试。单方说法可以入料，但服务器与人物归属仍须对上。

## B站频道调查

平台读法见[工具细节的 B站细则](research-tools.md#b站细则)，精选标准见列传规则的“B站 UP 作品精选”。本页只补查频道的做法：

- **先读空间，再定候选**：首次调查已对应 UP 或补精选时，先核空间简介、视频／图文数量、合集与系列；同一人物有多个已对应账号时逐个核，只在作品里被点名的候选账号不混作本人账号。分别看“最新发布”和“最多播放”，核对当前选中的排序并记实际页次，两者不互相替代；未查最多播放不能把最新页的高播放说成全频道最高。按创作主线、重要事件与系列补候选，不以补完频道为目标。
- **精选的判断**：多个本人账号合并去重后总共最多 5 个。本人带队、实战、教学和系列创作本身就是看点，简介只写“视频已加速”或评论少都不是排除理由，外网链接也不一律算不合格。首批读取上限不是整项上限。未读或受预算／访问限制的记未完成，不判成质量不足；仅见标题／计数的只留候选。
- “B站”是身份标签，不作别名，清理别名不连带删标签。

## 发现新人物

按名字找只能找回已知的人。以社区帖子、回帖和作者网络为主线，名册作补充；一条入口的零结果不能代替另一条：

1. **社区故事发现人物**：给贴吧帖子列表的“标题 + 首楼”打分：职务词（总监、CEO、团长）、冲突词（弹劾、背刺、澄清、骗、跑路、封号、悬赏）、叙事词（前传、始末、回忆、经历）加分，招新、交易、求助减分。叙事分与回复量是两条独立入口：回复量前列的中性帖单独排队，至少读首尾和楼中楼再决定是否读全文；数字加物品或事件词的标题也抽样读。同一吧、同一批的相对排名优先于固定阈值。
2. **按楼主 uid 聚合、追被点名者**：短期连发长帖的楼主可能就是名人；回帖多但只开过一帖的人也可能是关键人物。楼中反复出现的人名、`@`、别名和“这位就是……”“又是他”都转为候选并查重。用 uid 合并改名账号，保留原用户名和展示名。
3. 排除已读帖子号再看。列表接口只回溯到约 2024 年中，更早的用站内搜索加上述关键词。
4. **名册补充**：做法见[工具细节](research-tools.md#少用的补查入口)；发现人后仍回社区帖子找故事。
5. **联盟执行军团**：华人联盟还要查 ESI `executor_corporation_id` 对应的执行军团，优先逐个追现役角色的公开头衔、职责和社区事件，同人小号并回原人物。历史 CEO 和军团榜单不能代替现役名单。每轮首批最多十人，记任期、覆盖与未查项。

身份未对上才进 `docs/leads/` 与角色备忘录；未达门槛的先存素材、身份与来源，再追具体事件。

## 小号查漏

有需要才补查，不当每次修订的必跑清单。找到收录号不等于找全本人，也不以 KB 名字检索没出现为完成依据。

- **名字扩查**：从角色名、aliases 拆词根，查编号、大小写／形近字及用途前后缀。明确系列才用 ESI `POST /universe/ids/` 有限批量补查，不默认穷举编号。
- **EveWho 前缀搜索**：`/autocomplete/<小写且 URL 编码的词根>`，取 `suggestions` 中 `data.type == character`。每类最多 10 项，满额记截断，只在预算内拆有线索的分支；不做错拼容错。KB 自动补全可能漏掉无击杀的号。
- **军团榜单反查**：从当前或相关历史军团的高 KM 榜选少量候选，读头衔和完整简介，与全站中文名、别名及素材对照，可能找到英文名不同的小号甚至主号。榜单口径见[军团榜单](research-method.md#军团榜单与历史-ceo)。
- **身份核对**：结合自报头衔、角色互链、相近名字与当前／历史同军团、时间重合判断；同批建号、同步入退团可加固对应，只有“FC”等常见头衔或同联盟不足以合并。退团不抹掉已建立的同人关系。角色名以本人或当事联盟写法为准；同一外号可能指不同人。
- **补录**：同人的名字、ID、依据与来源按列传规则的“总方针”写入身份档案与本人素材；发现主号时记择号依据。未对上、未查和失败分别留缺口，不另立小号传。

## 监视者驾驶员反查

华人联盟或军团的 Monitor 驾驶员是高优先级 FC 主小号线索，主动从已取得的战报、KM 和船型榜查漏，不只查被点名者。按战时归属筛选；联盟有外语成员时继续核对军团、头衔与中文社区交集，不把整个阵营当华人个人。

先对照收录号、aliases 与素材中的历史小号，再查公开中文头衔、简介、同词根及当前／历史军团。明确对应的并入原人物；有独立故事且角色对得上的直接立传；未对应的在 `docs/leads` 备案并登记 pending-characters，至少写角色 ID、代表 KM、时间、战时军团／联盟、已查项和缺口。监视者说明参与指挥，不直接证明总指挥，也不能单凭同船型或同联盟合并真人。高值抽样未命中不当作没有驾驶记录。

按军团／联盟查驾驶员用[高级搜索](research-tools.md#zkillboard-高级搜索asearch)，月榜读取见[工具细节](research-tools.md#系统-chrome-月榜读取)。
