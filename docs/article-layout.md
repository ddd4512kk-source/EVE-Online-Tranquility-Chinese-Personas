# 长文排版：目录、小分页与折叠

本页管全站长文（天书、列传、战役、军团）的目录（TOC）、小分页（`::: 分页`）和可折叠块（`::: 折叠`）的语法、展示规则与判断步骤。写较长列传、收录或翻译较长官方新闻时读取；短篇或只改数据字段时不需读。视觉实现与无 JS 约束见[网站设计](site-design.md)，解析逻辑见 `scripts/article-prose.mjs`。

## 边界

- 本文组件只管信息组织与阅读体验，不改变正文事实、语气或审校标准；列传里增减 `<!-- toc: ... -->` 或正文内的折叠／分页不改变人物身份档案结构，也不要求改动 `<ID>-id.json`。
- 重组结构时**不得删改原文事实、数字、专名或图片**，不必拘泥官网原文的平铺或分节形式。
- **不得**把列传的 `::: 红料`、`::: 黑料` 主故事块或战役的 `::: 高潮` 块塞进分页或折叠内；`::: 分页` 与 `::: 折叠` 内部标题不进入页面目录。
- 合辑式补丁说明（`patch-notes-version-*`）仍须严格保留 `## **YYYY-MM-DD.N补丁说明**` 二级标题独占规则（见 `src/news/AGENTS.md`），不可把每日二级标题包进折叠或分页。

## 写作与排版判断步骤

撰写或整理超过约 2,000 字、或包含多段结构化清单／参数的文章时，在定稿前依次完成以下三项判断：

1. **目录（TOC）判断**：核对本文是否属于“需要跳读定位”的长文，决定沿用自动门槛，还是显式开启／关闭、以及是否收敛为二级目录。
2. **小分页（`::: 分页`）判断**：扫描全文，找出同一主题下 2–6 组并列同构的内容（如单舰多组属性、多势力同步器／装备、多方案参数），按玩家查阅习惯重组为分页块。
3. **折叠块（`::: 折叠`）判断**：扫描全文，找出 15 行以上的冗长名单／大表格、次要附录、或与正文重复的长段“图中文字”，收进自解释标题的折叠块。

## 语法与字段示例

### 1. 目录开关（TOC）

- **自动门槛（默认，无需手写）**：正文去标签纯文本满 2,500 字且目录项满 4 条，**或**目录项满 6 条时自动显示目录；少于 2 条永不显示。
- **收录对象**：天书与军团收顶层 `##`、`###`；列传收顶层 `##` 与 `::: 红料`／`::: 黑料` 标题（带红／黑圆点）；战役收顶层 `##` 与 `::: 高潮` 标题（带金圆点）。
- **自动深度收敛**：天书与军团的 `##` + `###` 总数超过 32 条且 `##` 不少于 8 条时，自动只列 `##`。
- **显式覆盖**（优先级：front matter > 正文注释 > 自动门槛）：
  - 有 front matter 的板块（天书、战役、军团）：
    ```yaml
    toc: true
    tocDepth: 2 # 可选，仅 2 或 3
    ```
  - 无 front matter 的列传（或任意 Markdown 正文顶部一行，渲染时自动清除）：
    ```markdown
    <!-- toc: on -->
    <!-- toc: off -->
    <!-- toc: on depth=2 -->
    ```

### 2. 小分页（`::: 分页`）

无需嵌套冒号；容器内用独立行 `=== 标签名` 切页，每页支持任意 Markdown（列表、表格、图片、引用、`::: 折叠`）：

```markdown
::: 分页 舰船参数
=== 特性

- 大型能量炮台伤害加成 15%

=== 防御

- 护盾容量：2,000 HP
- 装甲值：2,700 HP

=== 装配

- 高能量槽：7
- 中能量槽：3
:::
```

- 组标题（`舰船参数`）可省略，写上有助于区分同节内的多个分页块。
- 无 JS 时自动隐藏标签栏，按页名顺序全部展开可读。

### 3. 可折叠块（`::: 折叠`）

```markdown
::: 折叠 查看全部 37 个翻新 1 级任务地点

| 任务甲 | 任务乙 |
| --- | --- |
| 示例一 | 示例二 |

:::
```

- 默认收起；确需默认展开时写 `::: 折叠+ 标题`。
- 渲染为原生 `<details class="fold">`，零 JS 可用，Pagefind 全文搜索照常索引。

## 判定标准

### 何时显式控制目录

- **应开启（或保持自动）**：多板块资料片说明、合辑补丁说明、多红黑料（≥6 块）的人物长传、长篇战役复盘 → 桌面宽屏（≥1120px）右侧悬浮跟随，窄屏自动折叠在页头下方。
- **应指定 `tocDepth: 2` / `depth=2`**：主章节（`##`）已足够清晰，三级标题多达数十个会撑长侧边栏时。
- **应关闭（`toc: false` / `<!-- toc: off -->`）**：虽略长但一气呵成的叙事散文，或仅有零碎小标题、加目录反而割裂阅读。

### 何时用小分页 vs 折叠

| 场景 | 选用 | 正例 | 反例（不用） |
| --- | --- | --- | --- |
| 2–6 组并列同构内容，读者常逐项切看或对比 | `::: 分页` | 单舰的“特性／防御／电容与机动／装配”；四大帝国／五大海盗同步器；同类多件新装备参数；四大帝国战役成果 | 只有 1 组内容；两页篇幅相差十倍（一页 2 行、一页 100 行）；因果连续的叙事段落 |
| 冗长参考清单、大表格、次要附录、与下文重复的长段图中文字 | `::: 折叠` | 37 个翻新任务名单表；15 行以上改动细目；补充考据或超长原话引文 | 只有三五行的短列表；正文主结论或必须直接看到的核心图片 |

- **分页标签**：每组一般 2–6 页，标签控制在 2–8 字；同类属性多而碎时（如护盾、装甲、结构各自仅 3–4 行）可按逻辑归并成 3–4 页，避免点到手酸。
- **折叠标题**：必须写清里面是什么和体量（如“查看全部 37 个翻新 1 级任务地点”），不写“点击展开”“详情”这类空标题。

## 验收

- 天书运行 `npm run news:check`（校验 `toc`、`tocDepth` 与合辑补丁标题规则）。
- 核对生成页：桌面宽屏（1366px）确认右侧悬浮目录正常高亮、分页可切、折叠可开；窄屏（390px）确认目录默认折叠在页头下方、无横向滚动；深浅双色与无 JS 状态下全部内容完整可读。
