# 仓库统一标准

本页是代码、技术文档与数据维护的共同标准，适用于 Codex、Claude Code 和人工贡献者。目录指令负责定位，技能负责步骤；不按代理品牌维护两套写法。内容事实与文风仍以[内容规则](content-rules.md)、[写作验收](writing-review.md)和相应模板为准。

## 代码与文件

- 文本使用 UTF-8、LF、文件末尾换行；缩进使用两个空格。Markdown 段落不按固定列宽折行，保留有意义的换行和代码示例；不对正文、历史来源、快照或字体产物批量格式化。
- JavaScript 使用原生 ESM；Node 工具用 `.mjs`，浏览器脚本和 Eleventy 数据文件沿用 `.js`。内置模块写 `node:` 前缀，本地导入写完整扩展名；不混入 CommonJS，也不为风格统一迁移 TypeScript 或框架。
- JavaScript 字符串用单引号，含单引号时允许双引号减少转义，插值用模板字符串；语句写分号。箭头函数单参数省略括号，其余加括号；条件与循环有多条语句时用花括号。完整格式规则以根目录 `eslint.config.js` 为准，不另加冲突的格式化工具。
- 文件名使用小写与连字符；Eleventy 保留约定的 `*.11tydata.js` 等名称。变量与函数用 `camelCase`，类用 `PascalCase`，模块级固定常量可用 `UPPER_SNAKE_CASE`；对外已有字段、上游原始字段与游戏专名不因命名喜好更改。
- 技术说明、注释、测试名称和面向使用者的消息用中文；标识符用清楚的英文。注释说明原因、约束或数据口径，不翻译代码，不给简单函数堆模板注释。保留来源原文与外部协议约定。
- 一项规则只维护一处；调用现有档案读取器、统计与查询模块。模板负责呈现，计算字段负责适配，公共脚本负责解析与校验；不在模板、页面脚本和构建工具中分别重写同一算法。
- 函数围绕一项职责，优先显式参数和可测试返回值。命令行输出、联网与文件写入集中在边界；需要复用的模块不因 `import` 自动运行命令。错误保留上下文并向调用方传递，只有明确允许的缺失项才降级，不用空 `catch` 吞掉未知故障。
- 新依赖须确有用途，与 `package-lock.json` 一起更新，并保持 `package.json` 声明的 Node 支持范围。网站运行时仍遵守[网站设计](site-design.md)的纯静态边界。

## 数据与变更范围

- 人工判断、来源证据、抓取快照各按既有结构归档；不要把可推导结果再维护成另一份全员表。保留未知值的语义，不把缺数转成零，也不手填可由正式脚本生成的字段。
- 全部时间默认 UTC；完整时间戳使用带 `Z` 的 ISO 8601。历史来源的原时区可保留，但写入统一字段前须换算，不能靠去掉时区冒充 UTC。
- 修改现有文件时按本标准编写新增代码；不顺带重排、改名、重写无关代码。正文修订保留已认可的主线与素材，现有未提交和暂存改动必须保留。
- 改接口、档案结构或规则时，先找调用点及受影响文档；按[增量复查](review-workflow.md)保存人工结论与失效依据，不将一次代码通过误报为全量内容已复核。

## 自动检查与历史差异

`npm run lint` 对全仓 JavaScript 检查语法、已配置的安全规则和基本格式；`npm run doctor` 检查目录指令、技能副本与指令内的本地链接。两者接入 `npm run check`、构建预检与 CI。`.editorconfig` 提供编辑器默认值，不能代替检查。

取材目录含在浏览器或 REPL 环境执行的片段，暂不启用 `no-undef`；其他已配置规则照常检查。Node 工具、站点脚本与 Service Worker 分别使用对应的全局变量集合。工具链使用 ESLint 10 与 Stylistic 5，Node 最低兼容范围为 20.19+、22.13+ 或 24+（不支持 21.x、23.x），与 `package.json` 和运行时预检保持一致；日常使用沿用 `.nvmrc` 和 CI 的 Node 22。

`eslint-suppressions.json` 是首次引入统一规则时对既有格式差异的冻结基线，只豁免 `@stylistic/` 格式规则；没有豁免的文件必须通过全部已配置规则。旧文件逐步修正后，用 `npx eslint . --prune-suppressions` 删掉失效记录；不要运行 `--suppress-all` 或增加豁免来使新代码通过。只对本任务文件执行修复，不执行全仓 `--fix`。

ESLint 基线按“文件＋规则＋数量”计数，不能识别同一文件中一个旧问题被另一个新问题替换。因此它能阻止新增文件及既有文件的差异数量增长，不能证明每条新增代码已符合风格；修改旧文件时仍须检查新增部分。命名、注释语言、模块边界、Nunjucks/CSS 风格和叙事质量主要由代理通读验收，不声称已有全自动保障。

改脚本要有能暴露实际行为错误的回归验证，覆盖本次涉及的失败与边界路径；使用 `node:test` 和 `node:assert/strict`，测试不依赖真实网络或账号。修复需同时通过原有测试，不写只复刻实现的断言。完整验收命令和生成页检查见[开发与验证](development.md)。
