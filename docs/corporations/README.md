# 军团档案：按组织与历史月份复用线索

军团身份、榜单和人物调查从这里统一查询。每个军团使用稳定ID建立档案；同一角色出现在不同军团、月份或榜单时，只维护一份共享研究记录。具体事件和原话继续引用人物素材、共享来源及本目录的核读摘记。

```sh
npm run corporations -- list 宽带山
npm run corporations -- show 98626718
npm run corporations -- members 98626718 --scope monthly --period 2026-09
npm run corporations -- members 98626718 --scope all-time --offset 50
npm run corporations -- character 2120638286
npm run corporations -- members 99009082 --alliance --scope monthly --period 2021-09
npm run corporations -- source activity-2022-01
npm run corporations:check
```

所有命令均离线。默认每页10条、最多100条，`--offset`续页；分页数量不改变调查范围。`show`只返回组织概况与榜单覆盖，逐号内容用`members`或`character`。材料查询也支持`--kind corporation`和`--kind character`，名称、角色ID、已存昵称与公开账号组都可检索，不必先猜旧文件名。`notes/`的摘记按`source`类别参与材料查询及`--full-text`全文搜索。

## 存放与唯一维护处

| 位置 | 维护内容 |
| --- | --- |
| `<军团ID>.json` | 名称、带日期的简介／CEO／执行关系观察、历史榜单、公开账号组和材料引用 |
| `alliances/<联盟ID>.json` | 联盟范围榜单，与军团榜分开，不拆成推测的战时军团归属 |
| `characters/<ID末两位>.json` | 按角色ID末两位分片，唯一保存公开名片观察、已有调查判断、失败／排除信息、下一步和证据引用；每份使用`version: 1`和以角色ID为键的`records` |
| `sources/<key>.json` | 历史原表；尚未核定军团实体的行继续保留，不按同名候选强制归团 |
| `notes/` | 既有来源与核读摘记；原话、上下文、读取范围、旧失败和未核部分不因结构迁移丢失 |
| `origins.json` | 被合并表格的原路径、行数和校验值，仅用于追溯迁移，不维护调查批次 |

已收录人物的主小号和当前身份仍以`src/people/`正式人物档案为准。查询实时关联这些本地档案，不在军团档案另填“已收录”状态。共享角色的`review`是本项研究的唯一人工维护处；来源摘记中的旧收录报告不再续写，也不覆盖当前人物档案。

角色分片固定按ID末两位定位，例如`2120638286`在`characters/86.json`，不足两位左补零；角色换军团也不换存放位置。同一角色只能存于对应分片，直接维护该记录，不再生成或续写`characters.json`全员总表。查询单个角色只读一个分片，军团成员查询先分页再读本页涉及的分片；组织概况和精确名称／ID查询不读取共享角色。按角色昵称或其他关键词跨团查找、全量材料搜索与校验才遍历全部分片。

## 固定 Top 100，历史月份优先

- 榜单目标固定为Top 100。已有all-time榜只作找人hint，永久复用，不刷新、不校正排名、不为名单准确性重新取数。`recent`时间窗不明，不能代替自然月。
- 历史月份用`scope: monthly`与`period: YYYY-MM`标识。Monitor过滤榜使用`monitor-monthly`，与未过滤角色总榜分开。相同组织、口径和月份只存一份榜单。
- `target: 100`是统一目标，不代表已有100名或已调查100名。`entries`只保存实际已有名单；`acquisition`说明取得范围和缺口。来源返回不足100、只存了前50、已取得空榜、尚未取得分别说明，未知值用null，不把未知补成零。
- `refresh: never`、`purpose: hint`是固定约束。没有联网、刷新或自动补齐入口。本次只迁已有资料；缺名单和第51—100名的未调查范围继续保留，不能自动升级完成。
- 排名按角色计，不是去重后的自然人数。不同军团、月份、主小号统计不相加；历史榜也不是现役名册。

## 字段与阅读状态

组织档案`version`为1，`kind`区分`corporation`和`alliance`，`id`为正整数字符串且与文件名一致。`names`只记录已有名称与查找别称，名称及ticker仍复用全站名称表，不联网扩充。`observations`保存`kind`、统计`period`、观察`as_of`、`source`及原有字段；统计月、CEO核对日和实际任期不能互换。

每份榜单保留来源、取得日（未知为null）、取得说明、材料引用及`entries`中的名次、角色ID和原始数值。数值沿用字符串，避免改动历史精度和单位。`acquisition.state`的`captured`只表示现有记录称取得了该来源范围，`partial`表示只保存部分，`unknown`表示尚未取得；实际数量和边界仍看说明，取得成功不代表逐人核读。

共享角色的`profiles`仅是带来源的名片观察，不自动算成人工读完。`review.state`可为`legacy`、`unread`、`partial`、`reviewed`或`excluded`；迁移沿用`legacy`，表示已有旧判断但未在本次重新核定，可能只取得名单。`findings`原样保留既有判断与材料提示；有矛盾时并存，不按最新日期、最乐观结论或相同昵称自动裁决。`next_steps`保留具体待查，`evidence`指向阅读边界与上下文；以后人工复核时只更新此处及正式素材，不新增日期命名的状态表。

取得、名片核读、角色对应、故事消化、归档和入文仍是不同维度。查询中的`current_identity`从本地正式人物档案生成，只说明已归某人，不说明本次榜单、故事或所有小号均已调查。

## 迁移与验收

旧同构榜单的重复排名归并进组织档案，独有判断进入共享角色记录；简介、CEO、执行关系与历史原表按各自口径保留。长篇成员核读摘记按军团分开，跨军团段落只保留一份，旧章节引用随之调整。其他共享事件和人物素材继续使用原有归属，不复制正文。

修改后运行`npm run corporations:check`及全仓检查、测试和构建。检查只证明结构与引用有效，不能代替人工阅读、历史身份核定或真实平台验证。缺口以后在具体调查任务中处理，不因归档格式变化重新搜索。
