# 找料方法

给 AI 代理的取材操作手册。写列传前按这里的顺序找料；找到新的有效方法，补进本文件。本文件只写通用方法，不提具体人物、角色名或外号；人物材料与检索待办分别归入[人物素材库](materials.md)和[角色核对与待撰备忘录](pending-characters.md)。

## 〇、三条铁律（先读这个）

取材不全，常常是方法出了漏洞：把模板当配额、主动筛掉材料，或把搜索失败当成没有故事。以下三条用于避免这些问题，详见文末“常见取材漏洞复盘”。

1. **不筛料。** 找到的每一条有出处的料都要进列传。分量只决定**放在哪、写多长**，不决定**放不放**。轻料并进相关块或文末“杂料”块，不许丢。
2. **模板不是配额。** 模板里写了一红两黑，只是格式示例。料有十条就写十块。著名人物写成两三块的，几乎可以肯定是没找全。
3. **搜不到 ≠ 没有料。** 搜索被验证码拦、关键词撞了常用词、论坛搜不到中文——这些都是**搜索失败**，不是“此人没料”。失败要记下来，换渠道再找。

## 一、先弄清此人以什么出名

动笔前，先用一两句话回答：**这个人在圈里以什么出名？** 答不上来就不要开始写。来源：

- 已有素材与社区称呼（如以高安强暴闻名，强暴就必须是列传主线）；
- 代理自己的知识、普通网页搜索：只当**线索**，事实要回到下面的原始来源核实；
- **游戏数据画像**（见第二节第 1、2 步）：常用船、常去星系、待过的联盟，往往一眼就能看出此人是干什么的。

如果画像和已经找到的料对不上（例：击杀榜第一是 Catalyst、第一星系是 Uedama，料里却没有强暴），说明没找全，继续找。

## 二、必查清单（每人每项都要做，结果记进[人物素材库](materials.md)对应条目）

按顺序做。每一项都要在人物素材库对应条目写一行：查了什么、结果是“命中 / 零结果 / 搜索失败”。

### 1. 游戏数据画像（最可靠，必须最先做）

**一条命令拉齐**：`node scripts/research/profile.mjs <角色ID> [论坛用户名] > 画像.md`——输出头衔与简介全文、逐段军团当时的联盟、zKillboard 统计（常用船/星系/联盟/高价值月份）、论坛本人全部发帖和他人提及。下面各项是它做的事，也可以手动单查。


- **zKillboard 统计**：`curl -sL --compressed -A "Mozilla/5.0" https://zkillboard.com/api/stats/characterID/<ID>/`（不加 `-L` 会只拿到 302 空响应）。看 `topAllTime` 里的**常用船、常去星系、所在联盟**，以及按月的击杀/损失（哪个月数字异常大，就去看那个月发生了什么）。船名星系名用 ESI `universe/names` 解析。
  - Catalyst / Talos / Thrasher / Coercer + Uedama、Niyabainen、Perimeter = 高安强暴；
  - 某月 ISK 暴增 = 大会战（例：2014 年 1 月 = B-R5RB）。
- **单月击杀**：`https://zkillboard.com/api/kills/characterID/<ID>/year/<Y>/month/<M>/`，按 `zkb.totalValue` 排序看最贵的几张；`zkb.labels` 里有 `ganked`、`solo`、`titan` 等标签。
- **击杀详情**：ESI `killmails/<id>/<hash>/` 能看到此人在这张 KM 上的伤害（`damage_done`）、船型、所在军团联盟。伤害为 0 也是料。
- **每段雇佣的联盟**：EveWho/缓存只给军团名。对每个玩家军团调 ESI `corporations/<ID>/alliancehistory/`，对上此人在团的时间，查出当时挂在哪个联盟。CODE.、Safety.、Goonswarm 这类信息只藏在这一步。
- **ESI 角色头衔与简介**：`characters/<ID>/` 的 `title`、`description`（解码 `\uXXXX` 后读全文）。本人亲手写的，经常就是最好的料。
- **DOTLAN**（evemaps.dotlan.net）：军团/联盟事件史——CEO 交接、进出联盟、主权得失，带精确时间。用数字 ID 访问（`/corp/<ID>/events`、`/alliance/<ID>`），也可用于交叉核对角色对应。

### 2. 本人发帖全量

- **凛冬论坛**：先 `search/query.json?term=<英文角色名>` 找到论坛用户名，然后**列出此人全部主题和回帖**：
  `https://forums.winterco.org/user_actions.json?username=<用户名>&filter=4&offset=0`（主题，filter=5 为回帖，offset 每次 +30 翻页）。
  逐篇读原文：`https://forums.winterco.org/raw/<topic>?page=1`。**标题里带敏感词（强暴、骗、举报……）的帖子优先读，不许跳过。**
- 再搜别人怎么称呼他：中文外号、同音字、拼音、英文角色名及大小写变体分别试，看回帖和别人的回忆录里提到他的地方。
- 论坛搜索对中文词经常失灵，**用英文角色名和拼音外号搜**。

### 3. 贴吧 / 百度（社区八卦）

- **搜索顺序：先 Google（含贴吧快照）和必应，没东西再查百度和 B 站。** 百度、360 和 B 站接口都很容易限流，被拦后要冷却很久；先用不限流的 Google（代理自带网页搜索，加 `site:tieba.baidu.com` 或贴吧快照）和必应（`--bing`）把能搜的搜完，剩下的缺口再交给百度和 B 站。
- 欧服华人的八卦多半在 **百度贴吧 · eve欧服吧**，其次是 **eve吧**（国服旧账）、各人自己的吧。
- 代理自带的网页搜索多为海外引擎，对贴吧、知乎覆盖很差。**用 `scripts/research/baidu-search.mjs` 直接搜百度。**百度结果页摘要里经常带着帖子标题和楼层原文，足够引用。百家号文章可以用 `--page` 打开全文。
- 百度连续搜十来次会弹滑块验证码，脚本会输出 **【搜索失败】**。这时改用 `--so`（360 搜索）；360 被拦时页面标题是“访问异常”，脚本同样报【搜索失败】。360 也不行就用 `--bing`（必应国内版，对贴吧收录差，但英文角色名、B 站、知乎有时能搜到），以及代理自带的网页搜索（谷歌类，英文名、外网新闻、Reddit 较好）。百度用不了时，必应和谷歌**可以部分使用**，作为补充而不是主渠道。全部失败就隔一阵再搜，**并在取材记录里写明“百度/360 被拦，未搜完”**，不能当成没料。
- **外号与常用词重合时，中文搜索会被无关结果淹没。**一律加限定词（`eve`、`欧服`、联盟名、军团名），并改用英文角色名搜。结果全是无关内容时记为“零结果（外号撞词）”。
- **贴吧原帖被验证或 403 拦住时，追历史快照。** 同期转载、Reddit 与论坛回帖可能保留准确的 Wayback 时间戳和原帖 ID。找到链接后，普通回放不可读时可试 `https://web.archive.org/web/<时间戳>id_/https://tieba.baidu.com/p/<帖子ID>`，读取原始 HTML。只有存档确实存在且取回了正文才算命中；CDX / 可用性接口也可能 429、503。记录原帖、快照日期、可读楼层及来源边界，快照不是事件定论，也不保证保留后续全部回复。

- **可补试匿名客户端读帖。** `node scripts/research/tieba-client-read.mjs <帖子ID或网址> <临时输出.json> [最多页数]` 使用公开客户端的 POST `/c/f/pb/page` 协议，不需要登录或账号凭据；只用于取材，不接入构建。2026-10 实测部分网页端被验证拦住的帖子可返回主楼、部分楼中楼和原图链接；GET 的 110001 错误不能直接判为无帖。工具校验帖子号、页码及接口错误，分页受限或失败时标明部分读取。即使主楼分页结束，也不能保证已删楼、折叠楼、楼中楼全部返回。按楼号对应正文、署名、时间和截图；原始 JSON 可能含现实隐私，写在临时目录，整理后再归档。

- **贴吧原帖被验证码拦住时，用有头浏览器请维护者手动验证。** `node scripts/research/tieba-read.mjs <输出目录> <帖子ID>... [--search "关键词"]` 会打开可见的浏览器窗口，遇到百度安全验证就暂停，等维护者亲手完成后继续读；不用程序破解验证码。浏览器资料存在 `~/.cache/personas-browser`，可复用。实测（2026-10）未登录时新版贴吧只显示楼主正文和前几层楼（含楼中楼），后续楼层要登录；所以“读到原帖”要写明读到第几楼。验证刚通过时第一个帖子可能读成空页，需要重读。

批量搜索用 `node scripts/research/batch-search.mjs <清单.tsv> <输出目录>`：按节奏跑，百度→360→必应自动轮换，被拦会冷却重试，可中断续跑。实测（2026-10）两家国内引擎各二十多条就会被拦，必应对中文外号几乎无效——要分多次、少量搜，别指望一次跑完。

关键词组合（把“某某”换成中文名、外号、角色名分别试）：

| 目的 | 关键词 |
| --- | --- |
| 欧服吧里的评价 | `某某 eve欧服吧`、`如何评价某某` |
| 黑料方向 | `某某 封号`、`某某 吧主`、`某某 洗号`、`某某 骗`、`某某 RMT`、`某某 跑路`、`某某 叛逃`、`谴责某某`、`某某 强暴`、`某某 举报` |
| 国服旧账 | `某某 eve吧`、`某某 国服` |
| 人物整理文 | `某某 EVE领航员`、`某某 名人堂`、`某某 传奇` |
| 英文角色名 | `<角色名> eve`（常能搜到 B 站视频、官方论坛） |

### 4. B 站（重要信源，每人必查）

近年欧服华人的战斗录像、指挥视角、会议录音、招新广告和对线吵架，很多只发在 B 站，贴吧反而没有。B 站与贴吧同等重要，每人都要查。

- **工具**：`node scripts/research/bilibili.mjs <命令> <参数>`，匿名访问公开接口，不需要登录：
  - `user <关键词> [页]`：搜 UP 主；`search <关键词> [页]`：搜视频；
  - `videos <mid> [页]`：列 UP 主全部投稿（含简介摘要）；`info <mid>`：签名与粉丝数；
  - `video <BV号> [评论页数]`：视频简介、分 P、热门评论与楼中楼；`dynamics <mid>`：近期动态、专栏。
- **先找到本人账号。** UP 名常带数字尾巴或前后缀（如“某某123”），和外号对不上全称。`user` 搜中文外号时，逐页看候选，对粉丝/投稿较多的候选用 `videos` 看内容是否是 EVE；也可以搜英文角色名、军团名、`外号 + eve`。确认依据（简介写的军团、视频里的 BR 链接、招新群、维护者告知）记进素材库。
- **本人投稿全部列出。** 标题、简介逐条看：BR 链接对上 zKillboard 就是参战证据；简介里的招新广告能看出当时挂在哪个军团/联盟；简介里的吐槽、回怼评论往往就是料。
- **评论区与弹幕是料的主要来源。** 热门视频读 2–3 页评论；本人回复、对面阵营来骂、熟人揭短都记下来，注明“据某视频评论区”。
- **别人的视频里找他**：会战复盘、宁静周刊、对面视角录像，用外号和角色名搜。
- **限流**：连续请求会触发 412 / -352 风控，脚本自动冷却重试，三次仍失败报【搜索失败】；整个 IP 被拦后要冷却很久。所以先用 Google / 必应搜 `site:bilibili.com 外号`，找到账号后再用脚本；每次请求之间隔 10–20 秒，一个人的视频分批读。本机被拦时，代理自带的网页抓取工具（走另一出口）仍可读 `api.bilibili.com/x/web-interface/view?bvid=` 和 `x/v2/reply?type=1&oid=<aid>` 的公开 JSON，但它会经过模型转述，引用前要求逐字输出。被拦不能当成零结果。
- 找著名 FC 时，沿中文外号、UP 名称、英文角色名查指挥视角、会战录像和复盘，再与 zKillboard / 战报交叉看。击杀列表上的参战记录本身不证明由此人指挥。

### 5. 其他渠道

1. **知乎**：个人专栏、回忆文章、“如何评价某某”类问题。
2. **百家号 / 游戏媒体**：如“EVE领航员”的《晨曦名人堂》系列。
3. **PLA 论坛** forum.pla-eve.com：《EVE欧服华人势力大事记》（PLA 视角）。
4. **外网**：Reddit、官方论坛、EVE 新闻站——此人若在外国联盟待过（CODE.、Goonswarm……），英文圈可能有记录。

### 看到线索就追

- 摘要里出现“建议问问他……是怎么被干下来的”这类半句话，立刻换关键词追（例：`某某 吧主 撤职 eve欧服吧`），继续查请愿帖、撤职经过和各方回应。
- 本人教程里的“心得”往往是亲身经历：写跳货生存手册的人，去查他打掉过多少跳货。
- 搜到同一事件的多方说法时，都记下来。

### 原帖受阻后的快照与转载补查

- 百度原帖遇验证、删除或无法读取时，继续用 Google 等搜索人物名、外号、英文角色名、完整帖子标题及帖子号。分别加 `site:tieba.baidu.com`、`site:archive.org`、`site:archive.is`，以及“转载”“缓存”“快照”；搜索到的是摘要、原帖还是存档，须分清。
- [贴吧黑洞工具箱](https://tieba.in/)提供帖子快照检索。2026-10-07 实测匿名搜索跳转到登录页，未确认其是否覆盖目标贴吧和时间段；找到工具入口不代表已读到人物材料。没有已授权账号时，记录登录限制，继续查其他公开入口，不代替维护者注册、购买或申请监控。
- [Wayback Machine](https://web.archive.org/)、[archive.today 的贴吧存档索引](https://archive.is/tieba.baidu.com)和 [Common Crawl 索引](https://index.commoncrawl.org/)可按原帖 URL 查已有记录。逐个查普通、移动域名；只在查过的 URL 与索引范围内报告结果。某期 Common Crawl 无记录不代表所有快照不存在；403、429、5xx、超时仍是访问失败。
- CDX 查询的主机通配符可能匹配整个域名，不能以返回了数据就认定命中目标帖子。检查每条记录的原始 URL、时间和正文；不要下载无关的大批快照。
- Google 直连 HTTP 200 可能只是 JavaScript 跳转页；浏览器仍可能遇“异常流量”验证。确认取得实际搜索结果再记为命中或零结果，不能把这些页面当成空搜索。
- 找到转载或快照后，保留原帖链接、存档链接、捕获时间和可读楼层范围。核对发言署名与上下文，区分别人指控、当事人发言和作者点评；存档时间不是事件时间，只有标题或不明账号的截图不能替代正文。

## 三、料的轻重

给每条料估个分量，决定**放在哪、写多长**（不是决定放不放）：

| 分量 | 特征 | 处理 |
| --- | --- | --- |
| 重 | 多个独立来源、有录音/截图/KB、事件广为人知、对当事人名声影响大、**此人以此出名** | 单独成块，放在显眼位置，写足细节 |
| 中 | 单一但具体的来源（某帖某楼、某篇回忆、某张 KM），细节清楚 | 单独成块，写明“据某某” |
| 轻 | 只有一句吐槽、来源立场明显、或连原作者都存疑 | 野史本来就是 gossip：**来源弱但料够大的照样收**，注明“一说”“原文也怀疑”；来源弱、内容又鸡毛蒜皮的才不写 |

- 对手阵营写的料（如 FRT 写 AOM、PLA 写 FRT）照用，但标明出处立场，有对立版本就并列。
- 本人自述的“光荣事迹”与别人揭的短对不上时，并排放——这往往就是最好笑的地方。
- **不要替当事人“体面化”。** 社区黑话照写：强暴就写强暴（见 [glossary.md](glossary.md)），不要改成“多开”“PVP”这类中性词；带敏感词的帖子和事件不许绕开。只有现实隐私（真名、住址、单位、电话、照片）才需要先确认是否允许公开。

## 三之二、红黑怎么分，什么不算料

**黑料**只收此人自己做的、说的、能让他难堪或损害名声的事：吵架与公开冲突、滥用权限、食言、坑人、awox 团友、指挥失误、自相矛盾的言论、本人写的错字和自吹。

**账号盗窃按受害经历处理。** 不能将受害事实、雇佣日期或未经读取的帖子标题加工成他自盗、跑路的黑料。

**以下本身不是黑料**，最多作为中性背景写进“## 档案”小节，而且只在有故事时才写：

- 打赢或打输一仗、丢了贵船、被人拆了建筑——这是正常的游戏战斗；
- 击杀少、损失多、KB 一片空白——工业、管理、小号都很正常；
- 换军团、换联盟、AFK。

**这些可以作为故事背景**，具体红黑仍按人物言行划分：**去了对面阵营**、**联盟解散**。写清时间和当时两边的关系，不替任何一方定性。加入对面阵营、组织解散本身不构成本人黑料，须有具体言行或管理事件。

**这些也算不上料，直接不写**：

- “几年换了几家军团”这类跳槽统计——太普遍；

**KB 统计**（击杀数、常用船）可以作为**红料**留下，但**一两句话即可**，别写长；能支撑此人名声的（如常用船和活动星系与其知名玩法相符）可以多写一句。损失、KB 低不当黑料。

**立场**：本书写的是欧服华人社区，不是 FRT 的内刊。不要站在任何一方看对手：拆了 FRT 的星城、打赢 FRT，对那个人来说是战绩，不是黑料。

## 四、完成标准

列传可以收尾的条件：

- 第二节四项都做了，取材记录里每项都有结果（命中 / 零结果 / 搜索失败及原因）；
- “此人以什么出名”在列传里是**最重的一块**；
- 找到的有出处的料全部进了列传；
- 著名人物只有三四块料时，回头检查是不是哪一项没做或做失败了。确实只有这么多，就在取材记录里写明查过哪些地方。

## 五、已知的坑

- 角色名写法要以本人或当事联盟的写法为准，不凭同音字或搜索摘要猜写。
- B 站视频可能已删除；被删的视频无法确认作者时不要引用。
- 同一个外号或字母简称可能指不同的人，先用游戏数据或原帖交叉确认角色。
- Playwright 更新后浏览器可能丢失，报 “Executable doesn't exist” 时运行 `node node_modules/playwright/cli.js install chromium`。

## 六、主号找不到可用小号，角色对应不明时留备忘

取材前先看 [待确认角色备忘录](pending-characters.md) 与已有列传。优先找主号；找不到时，所有人物都可以使用确认属于本人的小号，无需再等主号或逐人申请例外。同一人的所有角色素材归在同一篇列传，不重复收录。没有可靠对应角色，或候选角色与人物对应不明时，立即写入备忘录，保留身份、事迹线索、原帖链接、候选角色和具体待确认问题。候选必须标明未确认，没有候选也可以登记。

角色对应可沿既有链接核对，也可以向老玩家询问；角色查不到不等于这个人不值得收录。拿到准确角色链接或 ID 并确认人物对应后，查重、继续取材和撰写，完成后更新备忘录状态。已确认角色但素材不足的情况记在人物素材库对应条目。

著名 FC 和其他收录人选，先完整登记。已有确认属于本人的角色而尚未写列传的，放进备忘录的“已确认角色，待取材撰写”，保留 B 站、战报和其他素材入口；不要只保存找不到 ID 的人。

## 常见取材漏洞复盘

| 漏洞 | 表现 | 修正 |
| --- | --- | --- |
| 模板被当成配额 | 不同人物都套用一红两黑，找到更多材料也不扩充 | 铁律 2；料有多少写多少 |
| 筛料、体面化 | 读到了帖子列表，却跳过带敏感词的标题，或把核心玩法改写成中性词 | 铁律 1；第三节“不要替当事人体面化”；按术语表使用社区说法 |
| 游戏数据排在最后、只看军团名 | 没看常用船与活动星系，没查每段军团当时的联盟，也没读完角色简介 | 第二节第 1 步必须最先做 |
| 只读搜到的零星帖子 | 没有列出本人全部发帖 | 第二节第 2 步：user_actions 全量列帖 |
| 搜索失败被当成“没料” | 验证码或脚本错误被当成空结果；外号撞常用词，结果全是无关内容 | 明确区分【搜索失败】与【零结果】；修复或切换渠道；外号撞词要加限定词或改搜英文名 |
| 没先问“此人以什么出名” | 列传写完仍未涉及人物最知名的事迹或玩法 | 第一节 |

## 七、材料归档与维护

- [人物素材库](materials.md)：每人一节，保存角色对应、故事、原帖、不同版本和检索结果。同一人的主号、小号与外号都归同一条目。
- [角色核对与待撰备忘录](pending-characters.md)：只记角色对应疑问、关联角色和待撰状态，详细材料链接到素材库。
- 本文件：只写通用取材方法、渠道限制和共用复核经验，不提具体人物、角色名或外号。术语与格式分别维护在 [glossary.md](glossary.md)、[person-template.md](person-template.md)。
- 新材料补到对应人物节，不按十人、二十人或调查轮次创建文件。已有列传须同步收录状态与源文件链接。
- 材料只保留人物事实、社区说法、原帖来源与待核对问题，不记录素材提供者的身份或与编辑的对话过程。游戏角色对应已确认，就直接写对应关系；尚未确认的，明确标注证据边界。

## 八、渠道复核与共用缺口

以下只归纳通用渠道限制与复核方法。各人的检索结果、历史料块数和待补材料归入人物素材库，不在这里列人物清单。

### 游戏资料与论坛

- 对当时已收录的 51 人重新运行画像和论坛取材，历史料块数曾从 188 增至 343。后来进行红黑重分，约 60 条普通丢船、低 KB、换团统计类内容改为中性背景或删除。这些数字不代表当前条数。
- 查管理人物时，曾检查 FRT、D.C 的 312 家成员军团，再读 CEO 资料、军团介绍和社区帖子。接口规模是角色数，不是真人数量；`ceo_id` 与实际掌事人分开。
- 画像、EveWho 雇佣、当时联盟及 zKillboard 返回数据，只代表对应渠道取得资料，不代表人物取材完整。已有列传的状态以当前源文件为准。
- 凛冬论坛 `user_actions` 返回零不代表本人没发过帖。旧导入帖子仍可能从主题读取；继续查带尾号的账号、旧站迁移记录与原主题。
- 用户资料隐藏或 `user_actions` 返回 404 时，可用 `search.json?q=@<用户名>` 补查公开旧帖，逐条核对 `username` 后读主题 JSON。作者限定搜索也可能返回他人文章，不能把不匹配的结果算作本人全量发帖；未覆盖范围继续记为受限。
- 论坛 HTML 常只展示前二十楼；`/t/<topic-id>.json` 可读公开正文，不能把首屏当整帖。搜索出现 `too many times` 或 429 时记录为失败。
- 主题列表只读第一页或返回零条，都不足以判断译者作品是否齐全；完整译作应沿 Wiki 栏目与署名继续追。
- DOTLAN 的名称页、holding 页与数字事件页可能有不同的访问结果；某一页能读不代表事件史已核实，旧 CEO 交接时间仍须交叉查证。

### 中文搜索、贴吧与视频

- 曾用批量工具查 400 条中文关键词，百度和 360 各二十多次后触发验证码；冷却重试仍被拦。必应中文外号多为无关页，要少量分段查。
- 无关结果、丢失人物关键词、验证码、403、超时均不等于人物没有故事。搜索结果未确认对应本人时，不能挪用其中的诈骗等指控。
- 近期热点须追完整原帖与各方回应；已有论坛和简介材料不替代热点原文。
- 仅取得精品索引或作者页摘要时，未读楼层不得冒充已核实；取得部分正文也须记录未读范围。
- 视频频道、同名 UP 与游戏角色之间须分别确认对应关系；找到入口不代表逐条视频、评论、知乎和新闻已经查完。
- 回应视频、采访截图及事件后续须继续读；视频标题不能替代对白或完整经过。
- 投诉帖须追读后续回复和双方解释；中文补查超时或遇验证时，可沿英文组织、成员名单和 ESI 查角色。

### 不写入正文的内容

- 角色简介中的 QQ、Discord 号码；涉及电话本等材料只写事件，不转载号码或现实姓名。
- 帖子中的现实照片，以及角色简介或聊天记录里的歧视性垃圾话。
- 普通丢船、换团频率、普通 AFK、教程篇幅和感叹号等凑数黑料。
- 账号盗窃按受害经历处理，不加工成自盗、跑路的指控或笑话。

继续取材时，按人物素材库的待补项追热点原帖、译者完整作品、具体争论、CEO 任期、虫洞管理旧事及比赛圈的独立故事。
