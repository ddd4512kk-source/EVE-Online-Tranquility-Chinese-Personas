# 取材手册

目的是**找故事**，不是凑完备档案。本页是列传、战役、军团共用的部分：怎么查已有材料、什么时候联网、各平台怎么读。写作与收录标准不在这里，按所属类型的规则。

专项另读：人物读[人物取材](research-person.md)；战役读[战役取材](research-battle.md)；军团先走 `add-corp` 技能的 `npm run corps -- clues`，需要榜单或任期时看下文[军团榜单与历史 CEO](#军团榜单与历史-ceo)。工具语法和少用入口在[工具细节](research-tools.md)。

## 取材原则

1. **搜不到 ≠ 没料。** 验证码、403、外号撞常用词都是搜索失败，记为【搜索失败】并停止该站请求，不当成零结果。
2. **找到就收。** 有出处的料全部入列。对立说法并列；本人自吹与别人揭短对不上时并排放——往往最好笑。
3. **先留素材，再判断能否写。** 留存与摘要要求见所属类型的规则，列传与线索见[列传素材归档](materials-person.md)；归属不明的进 `docs/leads/<短名>.json`。多人共用的事件摘要放 `docs/sources/<事件短名>.json`，人物素材只引用并补与本人有关的增量。叙述格式见[材料 JSON](materials-json.md)。
4. **野史不是科研，数字要量级。** 几十（10–99）、上百（100–199）、数百（200–999）、上千／数千（1000 以上）。能入文的是免费页面现成的汇总数或几张代表 KM；不为准确总数逐年、逐月、逐号扫描，不批量补全几百张 KM。一次请求能得到量级，就不发第二次。
5. **缺口留素材。** 第二来源、完整名单和准确人数不是普通社区故事的写作前提。低可信来源的名单与处理见[低可信来源](sources/low-credibility-sources.md)。

### 本地材料查询

- 跨人物／战役查漏或规则变更复查，先按[增量复查](review-workflow.md)筛候选、读相关段落并检查旧结论是否失效，不先加载数百篇全文。
- `npm run materials -- "人名／角色ID／事件词"` 定位正式档案与路径，搜素材正文及B站作品摘要加 `--full-text`；普通查询也支持作品标题与 BV／图文 key。结果不代表已核读、事件成立或调查完成，事件整合沿 `material` 读取，B站摘记按命中的 `archive`、作品 key 与字段读取；人物／战役素材引用的作品也参与全文查询。追旧备注或别名才加 `--history`（冻结的旧索引），当前身份、收录与阅读状态仍回查正式档案。
- 大榜单用 `npm run research:query -- <TSV路径> --where 列=值` 先筛再分页读，不整表加载、不另存状态副本。两个工具都离线，参数见各自 `--help`。
- 军团用`npm run corporations -- list <名称或ID>`定位，`show <军团ID>`看已有口径与缺口，`members <军团ID> --scope monthly --period YYYY-MM`分页查历史月榜，`character <角色ID>`跨团复用调查。档案与状态只维护在[军团档案](corporations/README.md)，不按调查批次另建队列。
- 跨平台身份用 `node scripts/person-identity.mjs <人物短名或角色ID>`；B站频道与作品用 `node scripts/bilibili-archive.mjs show <UID> [BV或图文key]`；术语用 `npm run glossary -- "词语"`。待认号与待撰事项沿[备忘录](pending-characters.md)及其原队列续查。

### 按增量安排下一步

- **先定位本轮缺口。** 已有具体事件先读原帖、公告和相关回复；已对应作者先追本人主题与互动网络；身份缺口先查头衔与角色互链，再做关键词发现。已知角色 ID 用查重、缓存或 ESI 解析，不为认名字重开 EveWho／zKB 网页。
- **检索看相关增量。** 普通词匹配、重复帖和他人发言不算新线索；出现新帖号、作者 UID 或具体事件才转入相应分支。顺带找到的他人材料按实际作者留存，不误归。
- **验收留存和续查价值。** 归档后重读新增段，核对关键原话、作者、来源和待核点都在；没读完不说读完。读过但无增量的分支留简短排除依据；评论加载失败留入口与状态，有具体恢复条件才再查，不把“补完频道／所有折叠回复”自动当下一轮任务。

## 联网条件与预算（所有取材入口共用）

先复用素材、快照和检索记录。只有新增线索、影响本次内容的未查缺口、记录矛盾或明确刷新要求才联网；普通修订、换会话、缓存到期都不触发重查。

- 请求上限、按站串行间隔和拦截冷却由 `scripts/research/request-guard.mjs` 强制执行，临时脚本也走它；报预算用尽就停，不换脚本、不重置冷却续预算。榜单首批最多 10 人，明确编号系列首批最多 20 个名字，优先批量解析。
- 连续 3 次关键词检索无新线索，停止该分支；403／429／412 停止相应入口，不自动换路径或出口（B站 API 与 Chrome 分开记录，见 [B站细则](research-tools.md#b站细则)）。其他验证码等人工处理，超时停止。冷却到期不自动重试，恢复须有具体未查需求。
- 预算触顶、分页未完、接口失败都记覆盖缺口，写实际 URL、读取方式、时间和状态；不为“全部读完”无限翻页，不猜接口。更大规模回查只在明确要求时另定范围与预算。失败判读见[工具细节](research-tools.md#请求守卫与失败记录)。

## 平台入口

按当前问题选入口，复用已有覆盖，不机械遍历；记录命中、零结果和搜索失败。

### 贴吧（eve欧服吧为主）

**先核服务器，再认人物和事件。** eve 吧多为国服内容，只在已有具体欧服交集线索时才查；PIBC 等跨服沿用的组织名、“EVE”字样不能证明欧服，eve欧服吧里的国服回忆也要区分。

- 命中 EVE 手游吧标【手游吧排除】并停止追查，旧队列同样适用。
- 明确国服且无独立欧服交集的标【国服排除】，撤出待收录队列，留简短来源摘要防止重复误收。
- 服务器不明的标【服务器待核】，不直接转为欧服故事；找不到欧服角色时，不把国服 ID 当中文外号。

正式处理状态统一在[贴吧档案](tieba/README.md)：每帖一个JSON，扫描范围记`scans.json`。先用`npm run tieba -- list`或`show <帖号>`查询，读后更新人工范围、图片缺口、归档与下一步；不另建日期命名的Markdown／TSV队列。

首选匿名客户端工具，不弹验证码（批量回查与续跑见[工具细节](research-tools.md#贴吧批量回查)）：

| 要做什么 | 命令 |
| --- | --- |
| 站内搜索 | `node scripts/research/tieba-client-search.mjs "eve欧服 关键词" 4 eve` |
| 翻帖子列表（约两年） | `node scripts/research/tieba-client-forum.mjs eve欧服 1 10 temp/frs.tsv` |
| 全帖回查 | `node scripts/research/tieba-client-read.mjs <帖子ID或网址> <临时.json> all --both`：正序和真正末页起的倒序主楼 + 每层全部可见楼中楼；再 `node scripts/research/tieba-client-dump.mjs <临时.json>`。原图用 dump 的 `--images <楼层数> <目录>` 下载 |
| 帖尾抽查 | `node scripts/research/tieba-client-read.mjs <帖子ID> <临时.json> 1 --reverse`；只看真正末页，不代表全帖完成 |
| 长帖分段阅读 | `node scripts/research/tieba-client-dump.mjs <临时.json> --floors 31:60`，含对应楼中楼；截断的终端输出不算已读 |
| 某账号发帖列表 | `tieba-client-user.mjs <帖子.json> <用户名片段> [1主题\|0回帖]` |

- 关键词带“eve欧服”；外号撞常用词时改搜事件词、联盟名、英文角色名。检索结果可能混入其他吧，逐条确认吧名；前三页没命中目标吧不算零结果。
- 搜索命中常只是一句回帖，点进主题读完整楼层。截图里的聊天人名、KM 常常就是角色名。
- 账号追踪同时核对展示名 `name_show`、原用户名 `name` 和 uid。展示名变成“贴吧用户_……”不等于没发帖；`hide_post=1` 只说明回复列表隐藏，转查主题、站内命中与他参与的帖。
- **楼中楼单独分页。** 主楼往往只带两条预览，按问题与预算读相关页；删除、折叠、计数滞后和限流都记缺口，不当无料。
- 抓取成功不代表人工已看。403/429 立即停止这一批并冷却，续跑不能跳过之前失败的条目。原始输出可能含现实隐私，只放临时目录。

### 搜索引擎

先 Google（代理自带网页搜索，加 `site:tieba.baidu.com`）和必应，最后才用百度/360（容易限流）：

- `node scripts/research/baidu-search.mjs "关键词 eve欧服吧"`；按需选 `--so`（360）或 `--bing`，被拦不自动轮换。
- 批量：`node scripts/research/batch-search.mjs <清单.tsv> <输出目录>`，固定引擎、每轮最多 10 条，缓存跳过，遇拦截整批停止。

### B站

先用 `npm run materials -- "人物或账号名" --kind bilibili` 查正式档案，命中就复用 UID／BV，未命中在素材记“待板块扫描”；不按人名、外号或角色名搜 B站。确实要联网读 B站时，再读工具细节的 [B站细则](research-tools.md#b站细则)，含读取限额、失败处理和扫描队列。

### 知乎与外网

知乎有当事人亲笔长答和事件对线，外国联盟、华人被老外爆料的戏多在外网。读法分别见工具细节的[知乎](research-tools.md#知乎)与[外网](research-tools.md#外网)；reddit.com 被拦不算读不到，按其中的替代入口读。

### 原帖读不到时

- 网页被拦：记录失败并停止，有具体新需要时再选其他公开来源。
- 帖子被删：Google 搜标题和帖子号，查 Wayback `https://web.archive.org/web/<时间戳>id_/https://tieba.baidu.com/p/<帖子ID>`、archive.is。
- 只有搜索摘要也能当来源，素材注明出处是摘要。B 站视频被删且认不出作者时不引用。

## 军团榜单与历史 CEO

先查[军团档案](corporations/README.md)，用 `character` 跨团复用。

- **榜单来源**：`api/stats/corporationID/<ID>/` 的 `topAllTime` 角色榜，别把近期 `topLists` 或有限榜单当全体成员。`/corporation/<ID>/top/` 默认当前月，`/top/year/<Y>/month/<M>/` 取指定月；`topAllTime` 不替代月榜，未标日期的 `topLists` 不推断为最近完整月。先看返回字段，再记实际窗口、榜长、取得状态和已核身份。
- **范围**：成员榜以 Top 100 为目标，具体历史月份优先。已有 all-time 榜永久复用，不刷新；旧前 50 只表示当时实际保存范围。缺口只有明确开展后续调查时才补，不因新年份、换会话或迁移自动补查。
- **历史 CEO**：军团旧事、踢人、封号或管理争议，看 DOTLAN 对应军团 `/events` 的 CEO 辞任／接任记录，按事件日期对上当时的 CEO 角色，再核历任角色是否同一人——DOTLAN 只记角色换任，不证明换了真人。EveWho、ESI 显示的现任 CEO 不能倒推旧事归属，小号入团日期也不是本人首次掌管军团的日期。任期、对应和事件日期记进素材，再写归责。
