# 找料方法

取材手册。目的是**找故事**，不是凑完备档案：找到能写的料就可以先立传，以后再补（门槛见 AGENTS.md 第 2 节）。本文件只写通用方法，不提具体人物；人物材料写进本人 `materials-<短名>.md` 或 `docs/leads/`。

## 一、取材原则

1. **先问此人以什么出名。** 那件事必须是列传最重的一块。画像（常用船、星系、联盟）和料对不上时，说明还有没找到的。
2. **搜不到 ≠ 没料。** 验证码、403、外号撞常用词都是搜索失败，记为【搜索失败】停止该站请求，不当成零结果。
3. **找到就收。** 有出处的料全部入列；轻料并进相关块。对立说法并列，本人自吹与别人揭短对不上时并排放——往往最好笑。
4. **先留素材，再判断能否写。** 搜索到或收到材料时，尽量保存原始内容/关键摘录、必要上下文、出处、时间、作者或说话者及角色对应线索。暂时不适合写、归属不明或尚未核实的内容，归入对应人物素材或 `docs/leads/`，写明待核问题/暂缓原因，留待未来补写或复核；不因当前用不上而丢弃。不得为存档而保留现实隐私。

**归档以 Markdown 总结精炼为主。** 读懂图片、聊天、PDF 等素材后，只保存事件经过、关键原话、上下文、人物对应、出处和必要待核点，不做全文转录、聊天流水账、文件名／哈希／排版备份，也不重复处理过程。多人共用的事件摘要可放在 `docs/sources/`，人物素材只补与本人有关的增量。不要批量备份图片或 PDF，只有文字无法替代的关键图才少量保存去隐私版本。

**取材记录交给写作时，要提炼故事。** 缺口留在素材；围绕已有事件整理人物处境、利益冲突、互相打脸的说法与可推演的动机。第二来源、完整名单和准确人数不是普通社区故事的写作前置条件。来源说法可以直接入文并交代来路，正文发挥与验收按 AGENTS.md 第 4 节和 [写作验收与改写例](writing-review.md)。

## 联网条件与预算（所有取材入口共用）

先复用素材、快照和检索记录。只有新增线索、影响本次内容的未查缺口、记录矛盾或明确刷新要求才联网；普通修订、换会话、缓存到期均不触发重查。军团榜单和名册跨人物复用。

- 请求预算是上限：关联人物首轮总计 30 次；EveWho 最多 8 次（搜索 4 次），zKillboard 搜索 6 次；失败、分页和跨脚本调用都计数。不自动续预算。
- 按站串行，EveWho 间隔至少 6 秒、ESI 1 秒、其他站 2 秒；有更严格规定时从严。榜单首批最多 10 人，明确编号系列首批最多 20 个名字，优先批量解析。
- 连续 3 次检索无新线索，或遇 403／429／412 即停止相应分支或站点；验证码可提示人工处理，等待无响应或超时才停止；不自动重试、换路径、换出口或整批转移到另一站。恢复须有新需要，遵守站点冷却要求。
- 预算触顶、分页未完、接口失败均记覆盖缺口；不为“全部读完”无限翻页，不猜接口，不把失败当零结果。更大规模回查只在明确要求时另定范围与预算。

HTTP 取材脚本有单次运行限额和按站间隔，拦截状态跨运行保存至少 30 分钟；任务仍须统一计算多个工具的总预算。临时 HTTP 脚本也用 `researchFetch`，或按已声明批次上限创建 `createRequestGuard({limit})`，默认共享停止记录；不重置冷却文件续预算。浏览器工具另限制导航／评论分页，验证码可人工处理，等待超时才停止。无需联网时请求为 0 次。

失败记录保留实际 URL、读取方式、时间与状态码。HTTP 200 挑战页记为挑战页，不能改称真实 403；某次抓取 403 不证明网页对正常浏览受限，更不证明功能不存在。共享冷却读取 `researchHostStoppedUntil(站点)`，兼容旧 `.cache/research-cooldown.json`；新事件写入对应 `.json.d/`，不靠手读旧文件判断是否能请求。

## 二、四类取材入口（记录命中 / 零结果 / 搜索失败）

按当前问题选择入口，复用已有覆盖，不机械遍历四项。

### 1. 游戏画像（定位人物时按需）

`node scripts/research/profile.mjs <角色ID> [论坛用户名] > 画像.md`

先复用快照与已有画像；资料缺失且影响本次判断时补跑。环境先用 `npm run doctor` 检查，旧 Node 报路径错误应修环境，不能据此弃用画像或重新手写一套请求。

按预算汇总：头衔与简介全文、每段军团当时所在联盟、zKillboard 常用船/星系/高价值月份、凛冬论坛本人主题与回帖；并非保证一次全齐，未查部分留缺口。重点看：

- 本人写的角色简介，常常就是最好的料；
- 常用船 + 星系暴露玩法（Catalyst/Talos + Uedama、Niyabainen = 高安强暴）；
- 某月 ISK 暴增可作战役检索线索，不能直接判定战役规模或个人功劳；
- 凛冬论坛标题带敏感词（强暴、骗、举报……）的帖子必读。

需要细查：zKillboard `api/kills/characterID/<ID>/year/<Y>/month/<M>/`（curl 要加 `-L`）、ESI `killmails/<id>/<hash>/`、DOTLAN 军团事件史。

**追历史 CEO 时查任期和角色归属。** 遇到军团旧事、踢人、封号或管理争议，打开 DOTLAN 对应军团的 `/events` 页，逐条看 CEO 辞任、接任记录，再用事件发生日期对上当时的 CEO 角色；接着核对历任角色是否属于同一人。DOTLAN 只记录角色换任，不证明换了真人。EveWho、ESI 军团页显示的现任 CEO，不能倒推旧事归谁管；某个小号的入团日期，也不能当作本人首次掌管军团的日期。把角色任期、本人对应和事件日期记进人物素材，再写归责。

**战役补漏。** 按各方总损失分大型（400B–不足 1T）与超级（1T 及以上）。综合 KB 与战役经历在同一红料里并列保留，正文结合人物处境、阵营与前后经历展开战斗并点评，不写成逐场报账后补一句俏皮话；列全已确认战役，记录窗口、阵营与参战／指挥依据，不以月度累计代替战报。

**先发现战役，再反查人物。** 大范围补漏先从 r/Eve 与 EVE 官方论坛的 AAR、战斗视频／复盘连载、招新帖中的 BR 找事件，个人 KB 作为补查入口。搜索搭配联盟全名／缩写、星系、`AAR`、`dread brawl`、`capital`、`battle report` 和战报域名；不只搜 FRT，不把标题是否写金额当作筛选门槛。评论中的修正版 BR、第二阶段和合并战报也要留存，长连载按实际读取页码记覆盖。

- 建事件清单：原帖与作者、发帖日、实际战斗日、全部 BR／related 链接、来源方说法、已核窗口／星系／分组／总损失、待核项。帖子标题金额只作线索；官方论坛里的玩家发帖也不是 CCP 官方定论。
- 多日累计、多场合计、结构与资产估值不冒充单场战损；同一场的分段／修订战报按 KM ID 去重，保留版本与窗口差异。宽窗口多星系 BR 中，人物仅在无关星系命中，不据此认定参加主战。
- 取得完整战报后，对照全部收录号与已对应主力小号，再查具体舰船、阵营和 Monitor／动员／复盘依据。高价 KM 样本可发现人，不能定整场金额，也不能用零命中排除参战。
- 共享事件摘要放 `docs/sources/`，人物增量归本人素材；只有战役规模与本人参战均有依据才补战绩正文。区分“候选发现”“战报已核”“人物已对照”“正文已增补”，入口失败或预算用尽记覆盖缺口，遵守本页停止规则。

**小号也查。** 从本人素材与别名取已对应的小号，按人合并战役；优先查 KB 参与击杀价值 ≥100B 的主力号。低值号可略过，有直接证据仍入料。高价值 KM 样本未命中时，再查主力号在该星系、该月的记录；不把样本零命中当未参战，不把各号累计直接相加。

### 2. 贴吧（eve欧服吧为主，eve吧只作低优先级线索）

**先核服务器，再认人物和事件。** eve 吧大部分内容来自国服，对本站属于低质量、低优先级线索来源，不作为默认补查入口。只有已有具体欧服交集线索时才查；命中后先核吧名、正文中的服务器、事件时间、角色与战时组织。同名人物、PIBC 等跨服沿用的组织名、中文角色名或“EVE”字样都不能单独证明属于欧服，eve欧服吧里的国服回忆也须区分。

- 明确属于国服、且没有独立欧服交集的事件，标为【国服排除】，撤出待收录队列；保留简短来源摘要防止重复误收。
- 服务器不明的材料标为【服务器待核】，不直接转为欧服人物故事；找不到欧服角色不是将国服 ID 当中文外号的依据。
- 已有欧服身份的人，其国服旧事须明确事件发生在国服并另记同人依据；不能因同名把国服争议移植给欧服角色。来源质量与爆料立场分开：单方说法可以入料，服务器与人物归属仍须对上。

首选匿名客户端工具，不弹验证码：

| 要做什么 | 命令 |
| --- | --- |
| 站内搜索 | `node scripts/research/tieba-client-search.mjs "eve欧服 关键词" 4 eve` |
| 翻帖子列表（约两年） | `node scripts/research/tieba-client-forum.mjs eve欧服 1 10 temp/frs.tsv` |
| 全帖回查 | `node scripts/research/tieba-client-read.mjs <帖子ID或网址> <临时.json> all --both`：正序和真正末页开始的倒序主楼 + 每层全部可见楼中楼；再 `node scripts/research/tieba-client-dump.mjs <临时.json>`。原图用 dump 的 `--images <楼层数> <目录>` 下载 |
| 帖尾抽查 | `node scripts/research/tieba-client-read.mjs <帖子ID> <临时.json> 1 --reverse`；只看真正末页，不代表全帖完成 |
| 建立回查清单 | `node scripts/research/tieba-review-inventory.mjs <临时目录>`；加 `--probe` 可续跑首楼/末页抽查，初筛结果不能算全文阅读 |
| 断点续跑全文 | 原命令加 `--resume`，读取同一 JSON 的覆盖记录，跳过已完成主楼页和楼中楼，保留旧错误历史；续跑帖号与顺序须与原文件匹配 |
| 更新覆盖清单 | `node scripts/research/tieba-review-status.mjs <临时目录> <覆盖.tsv>`，只导出帖号、引用文件、覆盖与错误，保留 TSV 的人工处理栏；不把成功请求自动写为已读 |
| 长帖分段阅读 | `node scripts/research/tieba-client-dump.mjs <临时.json> --floors 31:60`，含对应楼中楼；按实际楼层记录阅读范围，不把截断的终端输出算成已读 |
| 按冻结清单补全文 | `node scripts/research/tieba-review-batch.mjs <临时目录> [本轮最多帖数]`，顺序跑；复用首尾与已完成全文，保留计数差，限流整批停止；抓取完成不代表人工通读 |
| 某账号发帖列表 | `tieba-client-user.mjs <帖子.json> <用户名片段> [1主题\|0回帖]` |

- 关键词带“eve欧服”；外号撞常用词时改搜事件词、联盟名、英文角色名。
- 搜索命中常只是一句回帖，点进主题读完整楼层。截图里的聊天人名、KM 常常就是角色名。
- **角色对不上时，先读已取得的全文与帖尾，不只看截断摘要；未读部分保留缺口。** 长帖作者常在后期楼层贴游戏聊天记录（`[ 2025.02.28 13:44:48 ] 某某 > ……`），自己的角色名就在其中；先看最新楼层（网页“倒序”，脚本用 `1 --reverse`）。客户端 `r=1` 仅将当前页倒排，第一页仍是早期楼层，必须先取 `total_page`，再从末页读起；倒序 `has_more=0` 不能当作整帖结束。再拿帖中回忆的具体击杀（日期、船型、总值、掉落）去 zKillboard 对，用户名的变体（binkcn → Bink Wang）用 `npm run find` 试。检索脚本的结果可能混入其他吧，逐条确认吧名；前三页没命中目标吧，不算零结果。
- 账号追踪同时核对客户端的展示名 `name_show`、原用户名 `name` 和 uid。展示名变成“贴吧用户_……”时不能因此判断此人没发帖；`hide_post=1` 只说明回复列表隐藏，转查主题、站内命中与他参与的帖。
- **楼中楼必须单独分页。** 主楼的 `sub_post_list` 往往只是两条预览，按当前问题与预算读取 `/c/f/pb/floor` 的相关页，并用回复 ID 去重。记录声明数量、可见数量、页码与失败；分页结束但数量不足时仍记缺口，不能声称完整。删除、折叠、计数滞后和限流都不可当作无料。
- **回查要保存覆盖清单。** 分清“首尾抽查”“主楼分页完成”“楼中楼可见分页完成但计数有差”“阅读并归档”“正文已增补”。API 成功不代表人工已经看过；HTTP 403/429 立即停止这一批请求并冷却，续跑不能跳过之前失败的条目。
- 原始输出可能含现实隐私，只放临时目录。

### 4. B 站（与贴吧同等重要）

`node scripts/research/bilibili.mjs <命令>`：`user <关键词>` 搜 UP、`search` 搜视频、`videos <mid>` 列投稿（预算内分页）、`video <BV号> [评论页数]` 读简介与评论、`dynamics <mid>` 动态。

- **先查已有记录，别重复搜**：[素材索引](materials.md)和各人 `materials-*.md` 记着已对应的 B 站 UID、视频与播放数；脚本把成功响应缓存在 `.cache/bilibili/`（不入库），重跑同一命令复用缓存，确有刷新需要才加 `--fresh`。查过的结果（含零结果、搜索失败）一律总结进素材文件，换会话、换电脑也不必重搜。
- 先用 Google/必应 `site:bilibili.com 外号` 找账号，再跑脚本。B 站请求一多就锁 IP，**每人预算约 15 次**：
  1. `videos <mid>` 按预算分批拿标题与播放（无签名接口，每页 100 条自动翻页，不含简介）；
  2. 只挑最多 5 个明显有料的视频，用一次调用批量读：`video BV1,BV2,… 1`（每个视频只读一页评论，脚本自动间隔 20 秒）；
  3. 一旦报 403／429／412／-352，停止本任务所有 B 站请求，不换出口或接口继续抓；至少冷却 30 分钟，恢复仍需新需要。
- **跨平台认号看整条链**：先确认贴吧发言的 UID 与本人对应；若他用第一人称说“我做了什么”，紧接着贴同一事件的视频或主页，而 UP 名与其外号同名、拆字、谐音或惯用变体相合，就认定这是本人 B 站号，记 UID、视频和逐段对应依据，并更新列传 `aliases`、`B站` 标签。例：“焱”拆成“三火”再加“魔”，属于有来源链支持的名字变体。不要只因字面相近就合并无关账号。
- 评论区与弹幕是料的主要来源：本人回怼、对面来骂、熟人揭短都记下。
- 也在别人的会战复盘、周刊、对面视角里搜他。

### 知乎（有料，别跳过）

知乎有当事人亲笔长答（本人解释被封、联盟史专栏）和“如何看待某某事件”的对线，贴吧没有的细节常在这里。按需用有头浏览器工具；遇验证码提示人工处理，最多等待 10 分钟；无响应则停止，不自动换路径：

| 要做什么 | 命令 |
| --- | --- |
| 搜索（经搜狗知乎站内，知乎自带搜索未登录无结果） | `node scripts/research/zhihu.mjs search "关键词1" "关键词2" [页数]` |
| 读问题 / 文章与评论（预算内） | `node scripts/research/zhihu.mjs read <网址>...` |
| 列某人文章与回答（预算内） | `node scripts/research/zhihu.mjs user <主页或url_token>` |

- 宽泛关键词（“eve欧服”）九成是萌新问答，费验证码；搜事件词和人名：`eve FRT`、`如何看待 某联盟`、`某某 eve`。标题含“如何看待/如何评价”加事件的优先读。
- 评论区常有本人现身回复；“知乎用户”匿名答主可凭评论区署名或内容认人。

百家号“EVE领航员”、PLA 论坛 forum.pla-eve.com。

### 外网（外国联盟、华人被老外爆料的戏多在这里）

- **Reddit（r/Eve）**：reddit.com 网页、`.json` 都被拦，代理自带网页搜索也几乎搜不到具体帖。读帖一律用 `node scripts/research/reddit-thread.mjs <帖子ID或网址> <临时.json>`：走 pullpush.io 存档，打印正文和已取得的评论，未完分页留缺口（评论编号 ← 上级编号、作者、日期），原始数据存进临时文件。
  - 按关键词找帖：`node scripts/research/reddit-search.mjs "\"Army of Mango\"" [posts|comments] [subreddit=Eve] [条数]`（同走 pullpush）。网页搜索找不到帖子时，先找引用过 r/Eve 的英文二手文章（Talking in Stations 节目页、tagn.wordpress.com、imperium.news、New Eden Post），它们的链接列表常给出原帖编号。
  - **限流**：pullpush 对密集请求回 429（并声明不给代理免费抓取），Wayback 也会 429。脚本遇 429 立即退出；后续有新需要才评估恢复，不循环重试、不换站硬刷。
  - 存档接口一次最多回 100 条评论，脚本在预算内翻页，未完留缺口；不要把单次响应当全文，曾因此漏掉三分之二评论，包括认出当事人的那条。
  - 网址里 `?c=…` 这类分享参数不是评论编号，定位不到具体评论，直接读全帖。
  - 截图只有 `preview.redd.it` 链接，存档不描述图片内容；需要时另行下载。
  - 涉及华人的帖，评论区常贴贴吧或 B 站链接，顺着去读；爆料人常把军团介绍、联系方式昵称和角色名对起来，这类评论最有用。
  - 帖中说的角色名常有出入（缺前缀、拼写差一点）：ESI `POST /universe/ids/` 查名字，再看相关军团的 `ceo_id`、`creator_id`，用 `npm run find` 确认。
- **官方论坛**：forums.eveonline.com 的 `search.json?q=关键词`，多试几组英文关键词（人名、联盟名、事件词）。
- **凛冬论坛**（forums.winterco.org，有 `.json` 接口）：常有 r/Eve 戏的中文转述。
- **帖中链接的 Google Docs**：`/export?format=txt` 取全文。
- 结论按实际覆盖表述；未查渠道或被拦入口写缺口，不为证明“查不到”反复查询。

## 三、原帖读不到时

- 贴吧网页被拦：记录失败并停止；有具体新需要时再选择其他公开来源，不自动换工具重试。
- 帖子被删：Google 搜标题和帖子号，查 Wayback `https://web.archive.org/web/<时间戳>id_/https://tieba.baidu.com/p/<帖子ID>`、archive.is。
- 只有搜索摘要也能当来源写（“据某帖摘要”），不必因为读不到全文就放弃。

## 四、发现新人物

按名字找只能找回已知的人。改用：

以社区帖子、回帖和作者网络为主线，名册作补充入口；一条入口的零结果不能代替另一条：

1. **社区故事发现人物**：对贴吧帖子列表的“标题 + 首楼”按职务词（总监、CEO、团长）、冲突词（弹劾、背刺、澄清、骗、跑路、封号、悬赏）、叙事词（前传、始末、回忆、经历）加分，招新、交易、求助减分；叙事分数与回复量是两条独立的候选入口：高回复帖不因标题普通、招新、求助或首楼无冲突词而淘汰。数字加物品或事件词的标题也要抽样读，不能只看冲突词。将回复量前列的中性帖单独排队，至少读首尾和楼中楼，再决定是否扩为全文；同一吧、同一批的相对排名优先于固定阈值。
2. **按楼主 uid 聚合、追被点名者**：短期连发长帖、连开十来帖的楼主本身可能就是名人；回帖多但只开过一帖的人也可能是关键人物，不能只按发主题数筛。楼中反复出现的人名、`@`、别名和“这位就是……”“又是他”，都转为候选并查重；角色藏在回复里时，不能因为标题和楼主不是他就跳过。用 uid 合并改名账号，保留原用户名和展示名。
3. 排除已读帖子号再看。列表接口只回溯到约 2024 年中，更早的用站内搜索 + 上述关键词。
4. **名册补充**：CCP 各届 CSM 候选公告与竞选区、联盟锦标赛队伍名单、重大事件战报、军团管理名单可补漏，逐名对照本站列传、人物素材和待确认角色备忘录。候选公告中的 `Chinese`、`中文`、华人军团或联盟只是优先核对线索，不凭姓名、所在联盟或贴了中文版就认定与华人圈有关；参选和当选分开核对。发现人后仍要回到社区帖子找故事。

每次名单反查记下来源、覆盖的届次或事件、逐人的“已收录 / 新候选 / 关联待核 / 排除”及依据。只写“查过 CSM”不足以说明覆盖；未逐项对照的届次继续列为未查。查到本人公开竞选与角色对应、已有一件有出处的事，就按收录规则立传；身份未对上才进 `docs/leads/` 与角色备忘录。

有自己的故事（不只是别人回忆里路过一句）的人就登记或直接立传。仅有泰坦／超旗等战果签名、KM收藏和KB分析的，不自动立传；先保存战果、身份与来源，再追具体本人事件。已有职务或具体Monitor等指挥依据的FC，按AGENTS.md保留短篇。

## 五、已知的坑

- 角色名以本人或当事联盟写法为准；同一外号可能指不同人，用游戏数据或原帖区分。
- **小号查漏按下方触发条件执行，先检查已有覆盖。** 找到收录号不等于找全本人；不等别人逐个报号，也不以 KB 名字检索没出现为完成依据。
- B 站视频被删且认不出作者时不引用。
- Playwright 报 “Executable doesn't exist”：运行 `node node_modules/playwright/cli.js install chromium`。


华人联盟找人还须查 **ESI 联盟执行军团**：从 `executor_corporation_id` 取执行公司，优先逐个追现役角色的公开头衔、职责和社区事件；同人小号并回原人物。先复用现役名册、历史 CEO 和军团榜单，后两者不能代替现役名单。每轮首批最多十人，记任期、覆盖与未查项，再按线索展开。

## 六、小号查漏（有需要才补查）

沿已有身份线索选用以下入口，不把它们变成每次修订的必跑清单；统一遵守上方联网条件与预算。

- **名字扩查**：从角色名、aliases 拆词根，查编号、大小写／形近字及用途前后缀。明确系列才用 ESI `POST /universe/ids/` 有限批量补查，不默认穷举编号。
- **EveWho 前缀搜索**：`/autocomplete/<小写且 URL 编码的词根>`，取 `suggestions` 中 `data.type == character`。每类最多 10 项，满额记截断，只在预算内拆有线索的分支；不是错拼容错。接口说明见[公开源码](https://github.com/zKillboard/evewho/blob/master/www/controllers/autocomplete.js)。KB 自动补全可能漏掉无击杀的号。
- **军团榜单反查**：从当前或相关历史军团的高 KM 榜，选少量候选读头衔、完整简介，与全站中文名、别名及素材对照；可找到英文名字不同的小号甚至主号。使用 `api/stats/corporationID/<ID>/` 的 `topAllTime` 角色榜，别把近期 `topLists` 或有限榜单当全体成员。
- **月份口径**：`/corporation/<ID>/top/` 默认当前月，`/top/year/<Y>/month/<M>/` 取指定月。`topAllTime` 不替代月榜，未标日期的 `topLists` 不推断为最近完整月。先看返回字段与数据类型，再记录实际窗口、榜长、取得状态和已核身份；请求失败只留缺口。
- **身份核对**：结合自报头衔、角色互链、相近名字与当前／历史同军团、时间重合判断。同批建号、同步入退团可加固对应；只有“FC”等常见头衔或同联盟不足以合并。退团不抹掉已建立的同人关系。
- **补录**：明确同人的名字、ID、对应依据与来源写入 aliases 和本人素材，战役按自然人合并叙述，逐号统计与核对留素材，各号累计不相加。发现主号时记录择号依据；未对上、未查和失败分别留缺口，不另立小号传。

## 七、监视者驾驶员反查

华人联盟或军团的Monitor驾驶员是高优先级FC主小号线索，主动从已取得的战报、KM和船型榜查漏，不只查被点名者。按战时归属筛选；联盟有外语成员时继续核对军团、头衔与中文社区交集，不将整个阵营视为华人个人。

先对照本站收录号、aliases与素材中的历史小号；再查公开中文头衔、简介、同词根及当前／历史军团。明确对应者合并原人物；有独立故事且角色对得上者直接立传；未对应者在docs/leads备案并登记pending-characters。备案至少写角色ID、代表KM、时间、战时军团／联盟、已查项和缺口。监视者支持参与指挥，不直接证明总指挥，也不能单凭同船型或同联盟合并真人。复用共享样本，遵守统一预算；高值抽样未命中不当作没有驾驶记录，未全扫则说明范围。

### 系统 Chrome 月榜读取

已有明确浏览器读取需要时，运行 `node scripts/research/chrome-read.mjs <zkillboard网址> <.cache/输出前缀>`。WSL自动通过Windows Node连接系统Chrome，使用独立profile和仅本机CDP，不读取日常浏览器资料；保存正文、表格、角色ID及击杀链接。月榜后加 `ship/45534/` 可查Monitor，先核Top Ships确实只剩Monitor。KM的“List all pilots”需展开后再核零伤害驾驶员；默认名单不能算完整。导航仍计预算，验证未通过则停止并留缺口，不把打开窗口当取得数据。
