# 材料 JSON

内部材料统一存 JSON，公开正文与规则说明使用 Markdown。JSON 不只保存计数和标签，也保存完整中文的事件经过、多来源综合、人物关联、判断依据、矛盾与待核问题。材料内容的取舍仍按列传、战役、军团各自的规则；本页只定义共同存储格式。

## 内容归属

- 单篇 B站作品的内容、评论、作者回应与阅读边界，归 `docs/bilibili/<UID>.json` 的作品 `reading.digest`、`scope`。
- 人物、战役或军团独有的事件整理与采用依据，归本人／本场／本团目录的 `materials-<短名>.json`。
- 多人共用的事件、共同来源与相互冲突的说法，归 `docs/sources/<短名>.json`。各人物只引用这份记录并补本人独有的关联，不重复维护整件事。
- 未归属线索归 `docs/leads/<短名>.json`；军团共享角色与取材范围继续复用既有 `docs/corporations/` 专用档案。

按内容的共同归属选位置，不把多来源事件塞进其中一位 UP 的账号档案。文件和条目 ID 保持稳定，来源题目、人物称呼变化不改主键。

## 叙述材料格式

```json
{
  "version": 1,
  "type": "material",
  "title": "事件与人物关联",
  "sections": [
    {
      "id": "event-background",
      "heading": "事件经过与分歧",
      "level": 2,
      "content": "来源甲记下了事件前因；来源乙补充了当事人的回应。两者对时间的说法不同，尚缺能够定时的记录。\n\n判断采用哪一说及其依据写在这里，并保留[来源](shared-event.json#timeline)。\n"
    }
  ]
}
```

`title` 是材料题目，`sections` 按阅读顺序保存条目。每条有唯一稳定 `id`、`heading`、标题层级 `level` 和叙述 `content`；无标题的前导内容用 `level: 0`。`content` 不重复本节标题，读取器按 `heading`、`level` 生成标题；只有为无损保留旧标题排版时才使用可选 `heading_line`，它必须与标题字段一致。保留原文中的必要列表、表格、引语和相对链接即可，不把事件硬拆成逐句字段。事件经过、来源归属、分析与缺口应在叙述中说清，不能因同处一个字符串而混淆事实与推测。

引用材料用相对文件路径及 `#条目ID`；引用单作品同时给出 UID 档案及 BV／图文 key。旧显式锚点保留，已有回执保持历史原样；迁移不表示重新核读、审查通过或阅读范围扩大。

## 查询与迁移

先用 `npm run materials -- "关键词" --full-text` 定位，再用 `node scripts/material-document.mjs show <材料路径> [条目ID]` 读取。公共读取器将材料 JSON 投影为可按标题和行号查看的文字，查询与评审共用它，不另存一份 Markdown 镜像。`npm run materials:check` 校验正式材料结构并拒绝旧材料 Markdown 回流，接入全仓检查与构建；规则、README 与冻结历史不属于叙述材料。

格式迁移按原标题拆条目并核对文字完整性，不自动生成事件判断，不删除失败与排除依据。先迁移独有内容，再更新有效引用并移除旧材料文件；冻结历史索引和评审回执不重写。来源、人物身份和作品状态仍各在自身正式档案中维护。
