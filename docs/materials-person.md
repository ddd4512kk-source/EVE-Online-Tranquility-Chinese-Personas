# 列传素材归档

列传与人物线索接收、留存和清理材料的做法，不含写作要求。战役、军团的素材要求在各自规则里。

- **先留存，再决定是否入文**：搜索和接收材料时保留关键原文与必要上下文、出处、时间、作者／说话者和角色对应线索；暂不适合入文、无法归属或看不出用途的，也归档并写明待核问题或暂缓原因，不因当前用不上而丢弃。现实隐私不为留存而保存。
- **事件摘要用 Markdown 精炼**：外部图片、聊天记录、PDF 可能随时消失，读懂后把事件经过、关键原话、必要上下文、人物对应、出处和待核问题写进素材，不依赖原文件。不全文转录、不堆聊天流水账、不存文件名／哈希／原排版，不重复记处理过程。分清事实、来源方说法与推测，读不清的关键内容标出缺口，不补造。
- **少存二进制文件**：不批量备份图片或 PDF；只有文字无法替代的关键图才少量保留，并去除现实隐私。
- **B站结构化档案**：账号对应、频道 profile 与覆盖、作品公开元数据和状态统一放 `docs/bilibili/<UID>.json`，人物身份自动关联，不另存全员总表。具体事件、关键言论和作者回应归本人素材；视频、图文与旧专栏共用同一档案，与素材用稳定 UID／BV／图文 key 及素材锚点互链。流程见[档案说明](bilibili/README.md)。
- **军团结构化档案**：军团简介、CEO／执行关系观察、历史月份与固定all-time榜、公开账号组归`docs/corporations/<军团ID>.json`；跨团角色调查只维护一份共享记录，已收录身份仍从正式人物档案读取。榜单目标固定Top 100，已有all-time只作hint，不刷新；旧前50范围和缺失名单照实保留，不因迁移补齐或升级完成。不另建调查批次、日期命名的状态表；具体字段、历史未知实体与核读摘记见[军团档案](corporations/README.md)。
- 已收录人物的来源与检索记录 → 本人目录 `materials-<短名>.md`。
- 未收录或角色对不上的人，有独立事件或具体待查材料 → `docs/leads/<短名>.md`，并在 [docs/pending-characters.md](pending-characters.md) 登记一行；收录后移入人物目录。只有军团榜名片、同人账号对应及尚无故事的判断，归既有军团角色档案，不另建薄线索；共用事件已完整归档的，独有依据和缺口并回共享材料，备忘录直接指向正式档案。回顾一份线索时一并筛查同类重复入口，不等逐个点名；删除前保留独有证据、失败与排除依据、未读边界和具体待办，并更新有效引用。
- **材料位置不手填总索引**：`npm run materials -- "关键词"` 从人物、战役、来源、线索与 B站档案按需生成查询结果，用法见[取材手册](research-method.md#本地材料查询)。新增／迁移材料只改正式文件及确有待办的原队列，不另建人物总表、完成汇报或状态副本。旧索引已冻结为历史 JSONL，只按需检索，不能覆盖当前档案。
- **内部数据与清单**：ID、账号对应和多维状态用 JSON，同构榜单与逐行队列用 TSV，事件经过与原话用 Markdown；已有格式够用就复用，可推导结果不手填（见[仓库统一标准](repository-standards.md)）。迁移保留独有事实、失败与排除依据，未知保持未知，冻结历史不参与当前状态判断。只留未完成调查的队列、失败与排除记录，已完成的报告并入正式档案后删除，同一队列只维护一份状态表。
- **回顾材料时随读随整理**：再次阅读或修订某份素材时，检查其中的低价值操作流水账，如按日期记录“作品精选去重”“作品精选补足”、增删清单、完成汇报及重复状态。先将独有事实、来源、有效筛选依据、阅读边界和具体未完成事项并回对应事件或作品，再删除已无续查用途的记录；不按标题机械整段删除，不另写一份清理日志。新材料也不再追加这类流水账。只整理本次实际回顾的材料，不因此自动扩成全仓清理。
- 材料只写事实、说法和来源，不记录素材提供者身份或对话过程，不写“维护者确认”。
